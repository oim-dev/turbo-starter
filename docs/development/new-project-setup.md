# Установка нового проекта из Turbo Starter

Инструкция для агента, которому поручено установить новый проект по этой ссылке.
Результат — полученный шаблон, установленные зависимости и скиллы, импортированная
база Relay и работающие приложения с локальной инфраструктурой.

В этой сессии выполни только установку и проверку запуска, передай результат
пользователю и заверши работу. Проектные инструкции и скиллы предназначены
для новой рабочей сессии. Relay здесь только получает готовую базу из шаблона
и предоставляет Web-интерфейс.

Если не указаны имя проекта и каталог установки, уточни их. В примерах замени
`my-project` и путь установки. После скачивания выполняй команды из корня нового
проекта; при каждом вызове инструмента явно задавай этот рабочий каталог.
При продолжении прерванной установки сначала проверь уже созданные файлы и ресурсы.

## 1. Проверь среду

Нужны Node.js 24+, pnpm 11.25.0, Git, Docker Engine и Docker Compose v2+:

```bash
node --version
pnpm --version
git --version
docker version
docker compose version
docker ps
```

Установка нужной версии pnpm: `npm install --global pnpm@11.25.0`.
Проверь свободные порты и существующие окружения через `docker compose ls --all`.
Если стандартные порты заняты, выбери свободные и согласуй настройки ниже.

## 2. Получи шаблон и установи зависимости

```bash
pnpm dlx tiged@latest oim-dev/turbo-starter#main /путь/к/my-project
cd /путь/к/my-project
git init -b main
```

Tiged скачивает код без истории Git. Задай имя нового проекта в поле `name`
корневого `package.json`, затем выполни:

```bash
pnpm install --frozen-lockfile
pnpm run setup
```

Второй шаг восстанавливает проектные скиллы и собирает определения агентов.
Они понадобятся в следующей рабочей сессии.

## 3. Установи базу Relay из шаблона

Используй CLI и Server одного актуального релиза, не ниже 0.13.0.
Работай из корня нового Git-проекта. Исключи из окружения вызовов унаследованные
`RELAY_CONFIG` и `RELAY_SERVER_URL` другого проекта.

```bash
npx @oim-dev/relay-cli@latest --version
npx @oim-dev/relay-cli@latest init \
  --template https://github.com/oim-dev/turbo-starter.git \
  --template-ref relay-data \
  --name "my-project" \
  --slug my-project
npx @oim-dev/relay-cli@latest config get
```

В `--name` укажи название проекта, в `--slug` — его техническое имя.
`relay-data` — ветка базы шаблона. Команда переносит полную базу, включая все
документы, и создаёт независимый проект с собственным ID. Проверь имя и slug
в выводе и сохрани путь конфигурации для запуска сервера.

Первый коммит кода и origin для инициализации не нужны. При продолжении установки
используй уже созданную базу; прерванный импорт продолжай той же командой по подсказке CLI.
После импорта оставь данные базы в полученном состоянии.

Запусти Web-интерфейс, подставив абсолютный путь из `config get` и свободный порт:

```bash
npx @oim-dev/relay-server@latest --version
npx @oim-dev/relay-server@latest --config "<путь из config get>" --port 4700
```

Сервер — долгоживущий процесс. Запусти его в управляемом терминале или фоне,
сохрани идентификатор процесса или терминала для последующей остановки.

## 4. Настрой окружение приложений

В новой копии создай четыре рабочих env-файла:

```bash
cp infra/dev/.env.example infra/dev/.env
cp apps/nest-backend/.env.example apps/nest-backend/.env
cp apps/react-admin-panel/.env.example apps/react-admin-panel/.env.local
cp apps/next-web-app/.env.example apps/next-web-app/.env.local
```

При продолжении установки сохраняй существующие значения. Структура рабочих файлов
должна совпадать с примерами: меняются только значения переменных.

В `infra/dev/.env` задай собственные имена ресурсов:

```dotenv
COMPOSE_PROJECT_NAME=my-project-dev
MINIO_IMAGE=my-project-minio:dev
MINIO_INIT_IMAGE=my-project-minio-init:dev
```

Это выделит проекту отдельные Docker-контейнеры, сеть, volumes и образы.
Остальные dev-значения подходят для первого запуска, если порты свободны.
При изменениях согласуй связанные параметры:

| Настройка | Где согласовать |
| --- | --- |
| PostgreSQL | `POSTGRES_PORT`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` в `infra/dev/.env` и `apps/nest-backend/.env`; для backend на host — `POSTGRES_HOST=localhost` |
| S3 | `S3_PORT` задаёт порт в `S3_ENDPOINT` backend; `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` совпадают в обоих файлах |
| RabbitMQ | `RABBITMQ_URL` backend собирается из `RABBITMQ_USER`, `RABBITMQ_PASSWORD`, `RABBITMQ_PORT`, `RABBITMQ_VHOST` инфраструктуры |
| imgproxy | Порт `IMGPROXY_URL` backend соответствует `IMGPROXY_PORT`; `IMGPROXY_KEY` и `IMGPROXY_SALT` совпадают в обоих файлах |
| Client API | `CLIENT_API_PORT` соответствует порту в `FILE_PUBLIC_BASE_URL`, `IMAGE_PUBLIC_BASE_URL`, `NEXT_PUBLIC_CLIENT_API_URL` и `CLIENT_API_INTERNAL_URL` |
| Admin API | `ADMIN_API_PORT` соответствует порту в `VITE_BACKEND_URL` админки |
| Сайт и админка | `WEB_PORT` и `VITE_PORT` задают порты интерфейсов; их фактические origin должны входить в `S3_CORS_ALLOW_ORIGIN` инфраструктуры |

`S3_INTERNAL_ENDPOINT=http://minio:9000` остаётся внутренним Docker-адресом.
Используй `localhost` для локальных браузерных адресов. Убедись, что переменные
окружения процесса не подменяют настройки нового проекта.

```bash
pnpm env:check
docker compose -f infra/dev/docker-compose.yml config --quiet
```

## 5. Проверь сборку и запусти проект

До запуска dev-процессов проверь установку пакетов и сборку:

```bash
DOTENV_CONFIG_PATH=/dev/null pnpm build
pnpm agents:check
```

Работающая БД для этих команд не требуется. Затем последовательно запусти
инфраструктуру, примени миграции к новой БД и запусти приложения:

```bash
pnpm infra:dev:up
pnpm backend:prisma:deploy
pnpm dev
```

- `infra:dev:up` поднимает PostgreSQL, MinIO с инициализацией bucket, RabbitMQ и imgproxy.
  Первая сборка MinIO может занять несколько минут.
- `backend:prisma:deploy` подготавливает схему новой БД.
- `dev` запускает сайт, админку, Client API, Admin API и воркер изображений.

`pnpm dev` — долгоживущий процесс: используй управляемый терминал или фон
и сохрани идентификатор процесса или терминала для остановки.

## 6. Проверь готовность установки

```bash
docker compose -f infra/dev/docker-compose.yml ps -a
```

У PostgreSQL, MinIO, RabbitMQ и imgproxy должен быть статус `healthy`,
у одноразового `minio-init` — `Exited (0)`. Дождись сообщений о готовности
обоих API, сайта, админки и `Image worker connected`.

Проверь успешные HTTP-ответы и доступность интерфейсов по фактическим адресам:

| Что проверить | Адрес по умолчанию |
| --- | --- |
| Relay Web | http://localhost:4700 или выбранный порт |
| Сайт и админка | http://localhost:3000 и http://localhost:3001 |
| Client API | http://localhost:4000/docs и http://localhost:4000/openapi.json |
| Admin API | http://localhost:4001/docs и http://localhost:4001/openapi.json |

Убедись, что Relay Web показывает новый проект, сайт — стартовую страницу,
а админка — форму входа. Просмотри вывод запущенных процессов на ошибки.
На пустой БД Admin API создаёт владельца `admin/admin`; при заданном
`BOOTSTRAP_ADMIN_PASSWORD` используется указанный пароль. Keycloak первоначально выключен.

## 7. Передай результат и заверши установку

Оставь успешно запущенные сервисы работающими и сообщи пользователю:

- абсолютный путь нового проекта;
- фактические адреса сайта, админки, API и Relay Web;
- путь конфигурации Relay;
- результат сборки, миграций и проверок доступности;
- способы остановки процессов приложений и Relay Server;
- конкретные ошибки и незавершённые шаги, если они есть.

Для остановки приложений используется `Ctrl+C` в их терминале либо остановка
сохранённого фонового процесса. Инфраструктура останавливается командой
`pnpm infra:dev:down`, данные volumes сохраняются.

При ошибке сообщи её причину и не объявляй установку готовой. Отдельные отчётные
файлы, скриншоты и трассировки не нужны; результат передаётся пользователю в чате.

Заверши передачу сообщением с фактическим путём:

> Для начала работы завершите эту сессию и перезапустите агентский клиент
> из каталога `<абсолютный путь нового проекта>`. Новая сессия загрузит
> проектные инструкции и установленные скиллы.

После этого заверши установку. Работу с продуктом и Relay продолжит агент в новой сессии.
