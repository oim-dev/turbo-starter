# Изображения: контракт реализации

Контракт и план приёмки первой реализации. Изображения принадлежат этому проекту; отдельной
платформы доставки и версий изображения нет. Новая загрузка получает новый UUID.

## Инварианты

- Оригинал сохраняется отдельно и не перезаписывается после подтверждения загрузки.
- Все преобразования запускаются только подтверждением загрузки и повторами этого
  задания. GET никогда не запускает обработку.
- API и воркер — независимые процессы. RabbitMQ переносит идентификаторы заданий,
  imgproxy преобразует байты, воркер сохраняет производные в приватный S3 bucket.
- Хранилище подключается официальным JavaScript SDK MinIO (`minio`), включая
  presigned PUT/GET, stat, copy, чтение и запись. AWS SDK не используется.
- Обработка автоматическая, с сохранением исходных пропорций. Выбора геометрии
  и пресетов в публичном контракте нет.
- Размеры: шаг 200 px до 2000 px, без увеличения исходника. Конечная ширина
  включается всегда. Если положительный остаток меньше 100 px, предыдущая
  ступень заменяется конечной: `810 → [200, 400, 600, 810]`.
  При остатке ровно 100 px обе ступени сохраняются:
  `900 → [200, 400, 600, 800, 900]`. Маленький исходник получает свою ширину.
- Ранее опубликованные файлы сохраняют URL. Для старых записей manifest выбирает
  набор исходных пропорций, а при его отсутствии — один существующий набор
  одинаковой геометрии. Устаревшие поля хранения не открывают выбор пресетов
  через API и не приводят к смешению разных пропорций в одном `srcset`.
- Пользователь уточнил качество: «визуально без ухудшения», а не pixel-lossless.
  Оригинал побайтно неизменен. Производные: AVIF высокого качества и JPEG для
  непрозрачных фото либо PNG для прозрачности/неопределённого alpha. Исходная
  настройка: AVIF q80, JPEG q92, PNG без намеренной квантизации. Итог визуально
  проверяется на настоящих фото; уменьшение веса каждого файла не гарантируется.
  Метаданные удаляются, ориентация применяется, цвет переводится в sRGB.
  Каждый размер создаётся непосредственно из оригинала, без каскадного ресайза.
  Исключение подготовки источника — indexed PNG: imgproxy сначала создаёт
  полноразмерную TIFF-копию без потерь, снимающую ошибочную повторную квантизацию
  палитры. Все размеры затем создаются из неё. TIFF приватный и временный,
  оригинал неизменен; промежуточная копия не является публичным вариантом.
- Доступная сетка размеров передаётся вместе с вариантами. Фронтенд формирует
  `srcset` только из существующих файлов, а `sizes` определяется местом отображения.
  Нельзя подписывать файл 600 px дескриптором `800w`. Формат выбирается через
  `<picture>`/Unpic Source; URL каждого готового файла однозначен.
- `ready` публикуется после записи всего набора. Metadata/status не immutable;
  готовые URL уникальны и допускают immutable cache. Заглушка принадлежит UI.
- Admin API видит все изображения, Client API — только загрузки своего аккаунта.
  Публичны только обработанные варианты, исходники доступны авторизованно.
- Папка — одна необязательная строковая категория (включая путь `Каталог/Обложки`),
  теги — нормализованный список строк. Поиск по имени, заголовку и тегам; фильтры
  по папке, тегу, статусу. Перемещение меняет метаданные, а не S3 key.

## HTTP-контракт

Имена DTO и operationId определены backend и экспортируются через OpenAPI.
Frontend использует реальные generated exports, не ручную имитацию SDK.

- `POST /images/uploads`: JSON `{ filename, contentType, byteSize, title?, folder?,
tags? }`. Возвращает `{ image, upload: { url, method: 'PUT', headers,
expiresAt } }`. S3 PUT не получает JWT API. Повторять создание автоматически нельзя.
- `POST /images/:id/complete`: идемпотентное подтверждение. Возвращает ImageDto,
  HTTP 202 при незавершённой обработке, готовый объект при уже готовой загрузке.
- `GET /images`: `{ items, total, page, pageSize }`; query `page`, `pageSize`, `search`,
  `folder`, `tag`, `status`, `unfiled`. Стабильная сортировка новые сначала.
- `GET /images/facets`: `{ folders: [{ name, count }], tags: [{ name, count }],
total, unfiledCount }`, с учётом доступности пользователю.
- `GET /images/:id`: ImageDto; `Cache-Control: no-store`.
- `PATCH /images/:id`: `{ title?, folder?, tags? }`, без изменения оригинала.
- `POST /images/:id/retry`: только повтор неудавшегося исходного задания.
- `GET /images/:id/original`: авторизованное получение `{ url, expiresAt }`, no-store;
  временная ссылка MinIO скачивает оригинал как attachment.
- `GET /media/images/:id/:variantId`: публичная выдача ТОЛЬКО ready-варианта,
  без обработки, с корректным MIME, ETag и immutable cache.

ImageDto: `id`, `filename`, `title`, `folder: string | null`, `tags: string[]`,
`status: uploading | queued | processing | ready | failed`, `createdAt`, `updatedAt`,
`uploadedBy: { id, realm: admin | client, name, login }`, `original: { contentType,
byteSize, width: number | null, height: number | null }`,
`variants: ImageVariantDto[]`, `error: { code, message } | null`.

ImageVariantDto: `id`, `width`, `height`, `format`, `mimeType`, `byteSize`,
`url`. Все URL доступны браузеру и мобильному клиенту; localhost внутри контейнера
в публичные URL не попадает. Список `variants` выдаётся только после готовности набора.

Административные permissions: `images.read`, `images.upload`, `images.update`.
Исходники требуют `images.read`; повтор обработки — `images.upload`.

## Галерея

Маршрут `/images`, доступ из основной навигации при `images.read`. Самостоятельный
сквозной домен `domains/images` находится без группы: используется и административными,
и предметными сценариями. Связь аватара с аккаунтом принадлежит домену аккаунта,
использующему публичный API images. Группу media и общий frontend-пакет заранее
не создаём; контракт нескольких приложений обеспечивается backend и REST SDK.
Экран в `compositions/screens`, существующий
`infra/backend-admin-api` и generated Admin SDK. JSX только через генератор.

Главное действие — «Загрузить изображения». Слева/в мобильном фильтре папки,
сверху поиск, теги и статус. Адаптивные плитки с настоящими превью, именем,
геометрией и состоянием обработки. Drawer/modal с большим предпросмотром,
автором, датой, исходным размером, папкой/тегами и вкладками готовых файлов.
Вкладки называются по расширению: AVIF, JPEG, PNG; внутри — размеры и вес
файлов соответствующего формата. Доступны изменение классификации и повтор ошибки обработки.

Загрузка: выбор нескольких файлов, папка, теги, локальные превью,
индивидуальный прогресс/ошибки. Перетаскивание файлов на страницу открывает
загрузчик с принятой очередью; перетаскивание в открытое окно дополняет очередь,
сохраняя классификацию. Drop сам не отправляет файлы на сервер. События не должны
дублировать файлы, перехватывать обычный текст/URL или позволять браузеру открыть файл.
После PUT — complete; UI не ждёт конвертер.
Один опрос наблюдает pending в списке, подробностях и собственных загрузках,
включая скрытые фильтром; не таймер на каждую плитку.
Нужны состояния пустой галереи, пустого поиска, ошибки, загрузки и успеха.

## Проверки и владельцы

- Инфраструктура: отдельный фоновый general-agent, infra/dev и корневые infra scripts.
- Backend: отдельный general-agent, NestJS, Prisma migration, worker, OpenAPI и backend env.
- Frontend: отдельный general-agent, только React admin; SDK генерирует оркестратор.
- Зависимости устанавливает и lockfile меняет только оркестратор.
- Проектные агенты и их исходники/конфигурация не изменяются.
- Автоматические тесты backend не добавляются. Проверки: lint/types/build,
  ручные HTTP-сценарии на изолированной БД, визуальная браузерная приёмка
  в собственной agent-browser сессии. Артефакты в `.artifacts/<owner>/<task>/`.
- Для приёмки используется Compose-проект `image-pipeline-check`: PostgreSQL 5545,
  MinIO 19000/19001, RabbitMQ 15673/15674, imgproxy 18081. База `images_acceptance`
  отдельная; API 14000/14001 и admin UI 13001 не заменяют рабочие процессы.
  Сборка и проверки запускаются адресно, без генерации проектных агентов.

## Сценарии приёмки

1. Вход администратором, пустая галерея, загрузка фото с папкой и тегами.
   API быстро возвращает queued/processing, UI остаётся доступным.
2. После ready все варианты доступны, размеры сохраняют пропорции и соответствуют сетке,
   число файлов, MIME и вес совпадают с manifest. Preview использует srcset/sizes.
3. Прозрачный PNG сохраняет alpha, маленький исходник не увеличивается,
   повреждённый файл переходит в failed с понятной ошибкой.
4. Поиск, папка, тег, отсутствие результатов, пагинация и редактирование
   классификации работают после перезагрузки страницы. Автор и даты верны.
5. Client API не раскрывает чужие изображения и исходники; Admin видит загрузки
   обоих контуров. Разделение JWT и явные permissions остаются действующими.
6. Повтор complete не создаёт дополнительный набор. Перезапуск worker не оставляет
   вечный processing; повтор failed относится к тому же загрузочному заданию.
7. При недоступном конвертере API/список остаются доступны. GET отсутствующего
   варианта не создаёт queue jobs; готовый GET поддерживает cache/ETag.
8. Прямой S3 PUT работает из браузера; закрытый bucket не даёт анонимно читать
   оригинал. Повтор PUT staging после complete не меняет принятый оригинал.
9. Галерея проверяется на ширинах 390, 900 и 1440 px: нет горизонтального
   переполнения, диалоги доступны с клавиатуры, ошибки не уничтожают введённые
   поля. Скриншоты и результаты сохраняются в каталоге владельца.
10. Drop на страницу открывает uploader с выбранными файлами; повторный drop в
    окно добавляет файлы ровно один раз. Неподдерживаемые файлы имеют понятный исход;
    URL/текст не открывают uploader, отсутствие images.upload исключает загрузку.
11. Кнопка «Все изображения» сохраняет выравнивание и счётчик на desktop/mobile.
    Вкладки форматов показывают только соответствующие файлы и доступны клавиатурой.
12. Границы размерной сетки: 199, 200, 201, 299, 300, 800, 810, 899, 900, 950,
    2000 и 2001 px. `presets` отклоняется в create; ответ не содержит preset-полей.
