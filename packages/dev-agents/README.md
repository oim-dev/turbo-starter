# Пакет проектных агентов

Приватный workspace-пакет `@oim/dev-agents` содержит семь специализированных
ревьюверов и сборщик определений для OpenCode, Claude Code и Codex.
**Основной агент остаётся стандартным агентом среды.** Ревьюверы вызываются
для проверки и не подменяют разработчика или основной системный промпт.

## Источники

[Реестр](src/manifest.json) версии 1 содержит профили с `kind: reviewer`, например:

```json
{
  "version": 1,
  "agents": [
    {
      "name": "react-reviewer",
      "kind": "reviewer",
      "description": "Ревью React SPA и соблюдения React Reference",
      "prompt": "reviewers/react-reviewer.md",
      "skills": [
        "react-reference",
        "unit-architecture",
        "ts-styleguide",
        "tsx-styleguide"
      ]
    }
  ]
}
```

Поле `orchestrator` необязательно. Без него допустимы пустой список или набор
субагентов `worker`/`reviewer`: сборщик не создаёт конфигурации выбора главного агента.
При пустом списке профили отсутствуют, `agents-lock.json` содержит пустой `outputs`.

Прежний формат с явным `orchestrator` сохранён: он требует ровно одного агента
`kind: orchestrator` с совпадающим именем. Каждый агент задаёт `name`, `kind`,
`description` и `prompt` — путь к Markdown относительно `src`. Необязательный
`skills` — список уникальных имён установленных скиллов для предварительной загрузки
в Claude Code. Отсутствующий скилл останавливает сборку. Сейчас оркестратора в реестре нет.

Правила сопровождения сборщика — в [AGENTS.md пакета](AGENTS.md).
React-, Next.js- и архитектурный ревьюверы не привязаны к пути приложения.
Область и проверяемое состояние задаются поручением; применимые AGENTS.md, требования,
README, настройки и команды ревьювер находит в проверяемой области.

## Ревьюверы и порядок работы

| Агент                                                           | Область                                                                             |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| [react-reviewer](src/reviewers/react-reviewer.md)               | React SPA, сценарии UI и обязательное соблюдение React Reference и стайлгайдов      |
| [nextjs-reviewer](src/reviewers/nextjs-reviewer.md)             | App Router, SSR/RSC, гидратация, данные и обязательное соблюдение Next.js Reference |
| [nest-reviewer](src/reviewers/nest-reviewer.md)                 | HTTP, предметные операции, Prisma/миграции, очереди и ошибки NestJS                 |
| [architecture-reviewer](src/reviewers/architecture-reviewer.md) | Владельцы, профили, фасеты, колокация и граф зависимостей                           |
| [integration-reviewer](src/reviewers/integration-reviewer.md)   | Совместимость OpenAPI → SDK → адаптеры → интерфейс и сквозной сценарий              |
| [platform-reviewer](src/reviewers/platform-reviewer.md)         | Монорепозиторий, команды, env, Docker, worktree и готовность Git-шаблона            |
| [security-reviewer](src/reviewers/security-reviewer.md)         | Границы доверия, права, сессии, секреты и доступ к данным                           |

Основной агент задаёт цель, проверяемое состояние и базу сравнения, выбирает роли,
передаёт материалы и объединяет выводы. При полном аудите нужны все семь направлений;
при ревью изменений — затронутые направления и связанные потребители. Независимое чтение
можно выполнять параллельно, общие сборки и генерацию выполняет один назначенный владелец.
Ревьюверы не запускают других исполнителей и не исправляют найденное.

Обязательны [общий протокол](playbooks/review.md), а для React/Next.js также
[протокол соответствия референсам](playbooks/reference-compliance.md). Ревьювер самостоятельно
выбирает затронутые области reference, читает их документы и загружает нужные стайлгайды.
Новый и изменяемый код проверяется строго: работающий UI и зелёные проверки не оправдывают
обход подходов скиллов. Вывод содержит точные замечания и таблицу
«область → норма → код/доказательство → статус», включая неподтверждённые обязательства.
Запуск генератора нельзя доказать только структурой файла или опровергнуть отсутствием команды в diff.

React-, Next.js- и архитектурный ревьюверы выполняют любые браузерные действия только
через `agent-browser` в собственной изолированной сессии по общему протоколу.
Архитектурный ревьювер выбирает принятую архитектуру и проверяет её профиль и граф,
не навязывая Unit Architecture другим областям и не дублируя полное frontend-ревью.

Для вызова попросите основной агент использовать нужного ревьювера, указав область
и базу сравнения. Передайте фактические команды/результаты генерации, проверки и
согласованные решения. Один ревьювер не объявляет весь проект корректным и не подтверждает
чужую область вместо её проверки.

### Права и модели

- OpenCode: `mode: subagent`, запрет инструментального редактирования и делегирования,
  shell — с запросом разрешения. Модель наследуется; отдельный `default_agent` не создаётся.
- Claude Code: `model: inherit`, ограниченный список инструментов чтения, поиска,
  Bash и Web, `permissionMode: plan`, предварительная загрузка базовых скиллов.
  Write/Edit и Agent в список инструментов не входят.
- Codex: модель, sandbox, approvals и MCP наследуются от родительской сессии;
  standalone-профиль задаёт инструкции, но не создаёт отдельный read-only sandbox.
  Для технической изоляции проверяйте права родительской сессии. Запрет исправлений
  и обхода ограничений остаётся обязательным во всех клиентах.

Запрет Edit сам по себе не делает shell/MCP безопасными. Команды и браузерные проверки
должны соответствовать выданному поручению и изолированному окружению. Ограничения
инструментов указываются как блокеры, а не обходятся другим способом записи.

## Сборка и проверка

Скиллы, инструкции и готовые агентские файлы хранятся в Git. После получения
шаблона достаточно установить зависимости через `pnpm install --frozen-lockfile`;
отдельная подготовительная генерация не нужна.

После изменения исходников агентов выполните из корня проекта:

```sh
pnpm run agents:build
pnpm run agents:check
```

Ожидаемый результат — **7 агентов и 21 профиль**: по одному на роль для каждого
из трёх клиентов, плюс версионируемый `agents-lock.json`. `opencode.json`,
`.claude/settings.json` и `.codex/config.toml` для этого состава не создаются.
При переходе с прежнего состава сборка удаляет принадлежащие ей неизменённые профили
из `.opencode/agents/`, `.claude/agents/`, `.codex/agents/` и конфигурации
`opencode.json`, `.claude/settings.json`, `.codex/config.toml`. Вместе с ними удаляются
назначение кастомного главного агента и инструкции оркестратора, если они принадлежали сборщику.

OpenCode V2 подхватывает изменения автоматически; для принудительного обновления
используйте `/reload`. Перезапуск сервиса не требуется. Для чистого контекста начните
новую сессию со стандартным агентом: история существующей может содержать прежние
инструкции. Для Claude Code и Codex также начните новые сессии.

Общий `pnpm build` также включает пакет. Сборка приложений для работы с пакетом
не нужна; единственная инструментальная зависимость — закреплённый Prettier.
Изменения исходников, готовых профилей, общих конфигураций и `agents-lock.json`
сохраняйте в одном коммите. Задачи пакета выполняются без кеша, поскольку управляют
выходами в корне репозитория.

Доступны `--help`, `--root <каталог>` и `--format json`:

```sh
pnpm --silent run agents:check --format json
node packages/dev-agents/scripts/check.mjs --root /путь/к/проекту
```

Относительный `--root` считается от места вызова пользователя, в том числе через pnpm.
В другом корне ожидается та же структура источников и локальных инструкций.

## Проектные скиллы

Полный набор скиллов хранится в `.agents/skills/` вместе со вспомогательными файлами.
Источники и версии закреплены в корневом `skills-lock.json`:

- `react-reference` — клиентская React SPA; `nextjs-reference` — Next.js App Router и SSR.
- `ts-styleguide` — TypeScript во всех средах, включая backend и SDK;
  `tsx-styleguide` — React-компоненты; `postcss-styleguide` — CSS;
  `html-styleguide` — обычный HTML, не JSX.
- `unit-architecture`, `template-generation-ru`, `rest-api-codegen-ru`,
  `svg-sprites-ru` — профильные инструменты и архитектура.
- `relay` — рабочая память проекта; сохраняйте закреплённый в lock-файле commit,
  если отдельно не поручено обновить его.

OpenCode и Codex используют `.agents/skills/`, Claude Code — относительные ссылки
в `.claude/skills/`. Оба каталога входят в Git и доступны сразу после получения
шаблона или создания worktree. Готовые копии скиллов не редактируются вручную
и исключены из проектного форматирования.

Установка и обновление через Skills CLI — операция сопровождения шаблона,
а не шаг установки проекта. Для обновления существующего проектного набора:

```sh
pnpm dlx skills@latest update --project --yes
```

Новые скиллы и замены добавляйте через `skills add` с явными
`--skill <имя> --agent opencode claude-code codex --yes`;
удалённый скилл убирайте через `skills remove <имя> --yes`.
В одном коммите сохраняйте изменения `.agents/skills/`, `.claude/skills/`,
`skills-lock.json` и связанных инструкций. Перед коммитом выполните `pnpm run agents:check`.

## Владение файлами

- Генерируемые выходы и `agents-lock.json` хранятся в Git. Lock хранит владельца
  `@oim/dev-agents` и SHA-256 каждого результата без времени генерации.
- Сборщик удаляет только прежние неизменённые файлы из lock. Чужие файлы сохраняются,
  ручные изменения управляемых файлов останавливают сборку до первой записи.
- Старый владелец `@turbo-starter/dev-agents` принимается для миграции lock
  с теми же проверками владения и хешей.
- Генерируемые файлы и lock вручную не редактируются. Форматы выходов принадлежат
  [adapters.mjs](scripts/adapters.mjs); конфигурация управляется целиком, без слияния
  произвольных ручных полей.
- Одновременные сборки не поддерживаются. Публикация атомарна для отдельного файла;
  lock записывается последним.
- `check` только читает: сравнивает выходы и lock, проверяет необходимые локальные
  инструкции и Markdown-ссылки, включая пути к скиллам из репозитория. Корневой
  `AGENTS.md` и каталог `playbooks` необязательны; явно указанные источники и ссылки
  на отсутствующие документы остаются ошибкой. Якоря, внешние URL и содержимое
  скиллов не проверяются.

Сборки, проверки актуальности и локальных ссылок достаточно для сопровождения.
Отдельная тестовая инфраструктура профилей не требуется.
