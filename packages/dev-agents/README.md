# Пакет проектных агентов

Приватный workspace-пакет `@oim/dev-agents` сохраняет сборщик определений для
OpenCode, Claude Code и Codex. **Все кастомные агенты отключены и удалены**:
проект использует стандартного агента выбранной среды. Исходники прежних ролей
и сценарии оркестрации удалены.

## Источники

[Реестр](src/manifest.json) версии 1 сейчас пуст:

```json
{
  "version": 1,
  "agents": []
}
```

При пустом `agents` поле `orchestrator` должно отсутствовать. Сборщик не создаёт
профили или конфигурации сред, а `agents-lock.json` содержит пустой `outputs`.
Повторная сборка и `setup` сохраняют это состояние.

Существующий формат непустого реестра сохранён: `orchestrator` задаёт имя главного,
а элементы `agents` содержат `name`, `kind` (`orchestrator` или `worker`),
`description` и `prompt` — путь к Markdown относительно `src`. Непустой реестр
требует ровно одного оркестратора. Сейчас таких определений в пакете нет.

Общие правила находятся в [корневом AGENTS.md](../../AGENTS.md), правила сопровождения
сборщика — в [AGENTS.md пакета](AGENTS.md). Инструкции приложений выбираются по области
работы: [React Admin Panel](../../apps/react-admin-panel/AGENTS.md),
[Next Web App](../../apps/next-web-app/AGENTS.md), [Nest Backend](../../apps/nest-backend/AGENTS.md).

## Сборка и проверка

Из корня проекта:

```sh
pnpm run agents:build
pnpm run agents:check
```

Ожидаемый результат — **0 агентов и 0 выходных файлов**, кроме локального lock.
При переходе с прежнего состава сборка удаляет принадлежащие ей неизменённые профили
из `.opencode/agents/`, `.claude/agents/`, `.codex/agents/` и конфигурации
`opencode.json`, `.claude/settings.json`, `.codex/config.toml`. Вместе с ними удаляются
назначение кастомного главного агента и инструкции оркестратора.

После пересборки **перезапустите OpenCode и начните новую сессию** со стандартным
агентом. Существующая сессия может сохранять ранее выбранную роль. Для Claude Code
и Codex также начните новые сессии.

`pnpm run setup` восстанавливает скиллы из `skills-lock.json`, затем запускает эту
же сборку. Общий `pnpm build` также включает пакет. Сборка приложений для работы
с пакетом не нужна; единственная инструментальная зависимость — закреплённый Prettier.
Задачи пакета выполняются без кеша, поскольку управляют локальными выходами в корне.

Доступны `--help`, `--root <каталог>` и `--format json`:

```sh
pnpm --silent run agents:check --format json
node packages/dev-agents/scripts/check.mjs --root /путь/к/проекту
```

Относительный `--root` считается от места вызова пользователя, в том числе через pnpm.
В другом корне ожидается та же структура источников и локальных инструкций.

## Владение файлами

- Генерируемые выходы и `agents-lock.json` исключены из Git. Lock хранит владельца
  `@oim/dev-agents` и SHA-256 каждого результата без времени генерации.
- Сборщик удаляет только прежние неизменённые файлы из lock. Чужие файлы сохраняются,
  ручные изменения управляемых файлов останавливают сборку до первой записи.
- Старый владелец `@turbo-starter/dev-agents` принимается для миграции локального lock
  с теми же проверками владения и хешей.
- Генерируемые файлы и lock вручную не редактируются. Форматы выходов принадлежат
  [adapters.mjs](scripts/adapters.mjs); конфигурация управляется целиком, без слияния
  произвольных ручных полей.
- Одновременные сборки не поддерживаются. Публикация атомарна для отдельного файла;
  lock записывается последним.
- `check` только читает: сравнивает выходы и lock, проверяет необходимые локальные
  инструкции и Markdown-ссылки. Каталог `playbooks` необязателен; ссылки на
  отсутствующие документы остаются ошибкой. Якоря, внешние URL и содержимое
  установленных скиллов не проверяются.

Сборки, проверки актуальности и локальных ссылок достаточно для сопровождения.
Отдельная тестовая инфраструктура профилей не требуется.
