# Сопровождение проектных агентов

Инструкция относится к этому пакету и выходам `.opencode/agents/`,
`.claude/agents/`, `.codex/agents/`, `opencode.json`, `.claude/settings.json`,
`.codex/config.toml` и `agents-lock.json`.

- `src/manifest.json` — реестр семи ревьюверов с `kind: reviewer`. Поле `orchestrator`
  отсутствует: основной агент остаётся стандартным агентом среды. Не добавляй настройки
  выбора главного агента только из-за непустого списка субагентов.
- Сохраняй поддержку пустого реестра, набора только субагентов и прежнего явно заданного
  оркестратора. Без `orchestrator` сборка не создаёт конфигурации выбора главного агента;
  устаревшие неизменённые управляемые выходы удаляются по `agents-lock.json`.
- `kind: reviewer` задаёт режим без исправлений. Базовые скиллы из `skills` проверяются
  по установленным файлам и предварительно загружаются в Claude Code; в остальных
  клиентах их загрузку задаёт профиль. Модель наследуется от среды.
- Общие правила ревью находятся в `packages/dev-agents/playbooks/review.md`, проверка
  следования React/Next.js Reference — в `packages/dev-agents/playbooks/reference-compliance.md`.
  Нельзя сводить её к lint/build или пропускать нарушение обязательной нормы как «вопрос стиля».
- Рабочие требования и состояние проекта принадлежат Relay. В пакете описывается
  способ работы, а не копия проектной памяти. Установленный скилл не редактируй.
- Проектные скиллы устанавливай и обновляй через Skills CLI; `skills-lock.json`
  обновляет CLI. Общий источник — `.agents/skills/`, ссылки для сред создаёт установщик.
  Для генерации используй `template-generation-ru`. React SPA и Next.js имеют
  самостоятельные reference-скиллы; каноны кода принадлежат отдельным стайлгайдам.
- Скиллы, ссылки `.claude/skills/`, исходники и результаты генерации агентов,
  общие конфигурации сред и оба lock-файла хранятся в Git. Сохраняй изменения
  источников и готовых файлов вместе; относительные ссылки не заменяй абсолютными.
  Установка проекта и создание worktree не скачивают скиллы и не требуют
  подготовительной генерации. Личные настройки и credentials в Git не добавляй.
- Пути в инструкциях указывай от корня репозитория, Markdown-ссылки — относительно
  документа. Проверь наличие источников обязательных инструкций.
- Генерируемые файлы и lock вручную не редактируй. После готовности всех источников
  один исполнитель запускает из корня `pnpm run agents:build`, затем `pnpm run agents:check`.
  Конкурирующая генерация не поддерживается.
- Чужие файлы и ручные изменения управляемых выходов сохраняй; не обходи проверки
  владения и SHA-256. Возможности и модели стандартных агентов наследуются от среды.
- При изменении формата OpenCode применяй скилл `opencode` и официальную документацию V2.
  Форматы Claude Code и Codex сверяй с их текущей документацией и установленными версиями.
- Достаточны сборка, read-only проверка актуальности и необходимых ссылок. Не добавляй
  отдельную тестовую инфраструктуру или проверки точных формулировок промптов.
- Корневой AGENTS.md проверяется при наличии; отсутствие необязательного файла
  не блокирует проверку. Явно указанные источники инструкций и ссылки на скиллы
  обязательны и не пропускаются из-за их размещения в `.agents/skills/`.
- При пустом реестре проверь отсутствие прежних управляемых профилей и настроек главного.
- При наборе только ревьюверов проверь 21 профиль для трёх клиентов, отсутствие
  `default_agent`, выбора агента Claude Code и подмены основных инструкций Codex.
  Не заявляй общий read-only sandbox: права shell и Codex наследуются от родителя;
  подтверждай ограничения каждого клиента по документации и не обходи их инструкциями.
- OpenCode V2 подхватывает изменения конфигураций и скиллов автоматически;
  при необходимости используй `/reload`, а не перезапуск сервиса. Смена файлов
  не удаляет уже загруженные инструкции из истории: для чистого контекста начни новую сессию.
