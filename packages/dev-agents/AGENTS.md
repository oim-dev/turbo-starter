# Сопровождение проектных агентов

Применяй корневой `AGENTS.md`. Инструкция относится также к выходам `.opencode/agents/`,
`.claude/agents/`, `.codex/agents/`, `opencode.json`, `.claude/settings.json`,
`.codex/config.toml` и `agents-lock.json`.

- `src/manifest.json` — реестр. Сейчас `agents` пуст, поле `orchestrator` отсутствует:
  проект использует стандартного агента среды. Кастомные роли и сценарии оркестрации удалены.
- Сохраняй поддержку пустого реестра: сборка не создаёт профили и настройки выбора
  главного агента, удаляет прежние неизменённые управляемые выходы по `agents-lock.json`.
  Повторная сборка не должна восстанавливать удалённые роли.
- Рабочие требования и состояние проекта принадлежат Relay. В пакете описывается
  способ работы, а не копия проектной памяти. Установленный скилл не редактируй.
- Пути в инструкциях указывай от корня репозитория, Markdown-ссылки — относительно
  документа. Проверь наличие источников обязательных инструкций.
- Генерируемые файлы и lock вручную не редактируй. После готовности всех источников
  один исполнитель запускает из корня `pnpm run agents:build`, затем `pnpm run agents:check`.
  Конкурирующая генерация не поддерживается.
- Чужие файлы и ручные изменения управляемых выходов сохраняй; не обходи проверки
  владения и SHA-256. Возможности и модели стандартных агентов наследуются от среды.
- При изменении формата OpenCode применяй скилл `opencode` и официальную документацию V2.
  Форматы Claude Code и Codex сверяй с их текущей документацией и установленными версиями.
- Достаточны сборка, read-only проверка актуальности и необходимых ссылок. Не добавляй
  отдельную тестовую инфраструктуру или проверки точных формулировок промптов.
- При пустом реестре проверь отсутствие прежних управляемых профилей и настроек главного.
- После изменений конфигураций OpenCode требуется перезапуск. Уже работающие агенты
  не получают новый профиль от замены файла. Указывай это в результате настройки.
