# Turbo Starter

Fullstack-шаблон на **TypeScript, pnpm и Turborepo** для проектов с веб-приложением,
административной панелью и backend. Все приложения, общие пакеты и локальная
инфраструктура входят в комплект.

## Что внутри

| Приложение                                                   | Назначение                                                                                                           |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| [`apps/web`](apps/web/README.md) | Next.js 16, React 19 и Mantine. Стартовая страница с серверным рендерингом и подготовленная интеграция с Client API. |
| [`apps/admin`](apps/admin/README.md) | React SPA на Vite и Mantine: пользователи, роли, настройки входа, изображения и файлы. |
| [`apps/backend`](apps/backend/README.md) | NestJS 11, Prisma и PostgreSQL: отдельные Client API и Admin API, воркер обработки изображений. |

Готовые возможности:

- Клиентские и административные аккаунты, вход и профиль, роли и права доступа.
  В админке дополнительно поддерживается вход через Keycloak.
- Медиатека: загрузка изображений, поиск, папки, теги, предпросмотр
  и фоновая подготовка размеров и форматов.
- Файлы: загрузка в S3, история версий, выбор текущей версии,
  постоянные ссылки, просмотр и скачивание.
- Два типизированных REST SDK из OpenAPI, общие пакеты конфигураций
  в `packages/`.
- Docker Compose с PostgreSQL, MinIO, RabbitMQ и imgproxy в `infra/dev/`.

Веб-приложение содержит основу для будущего интерфейса; готовые экраны управления
находятся в админке. Keycloak подключается через её настройки.

## Разработка через Relay

**Relay — база знаний, задач и истории разработки проекта.** В нём хранятся
требования, проектные решения и документация, критерии приёмки, планы, релизы
и результаты работы. Код, конфигурации и команды запуска находятся в репозитории.

Знания и ход разработки доступны команде в Web-интерфейсе Relay;
адрес определяется настроенным подключением проекта.
Правила работы AI-агентов — в локальных инструкциях
[админки](apps/admin/AGENTS.md), [сайта](apps/web/AGENTS.md)
и [backend](apps/backend/AGENTS.md).

Для независимого ревью подготовлены семь [профильных агентов](packages/dev-agents/README.md):
React, Next.js, NestJS, архитектура, интеграция, платформа и безопасность.
React/Next.js-ревью отдельно проверяет соблюдение обязательных референсов и стайлгайдов,
а не только работоспособность кода. Основной агент среды не заменяется.

## Подготовка и запуск

Создание нового проекта из шаблона описано в
[отдельной инструкции](docs/development/new-project-setup.md).
Ниже — подготовка и локальный запуск проекта из текущего репозитория.

Требуются **Node.js 24+**, **pnpm 11.25.0**, **Git**, **Docker Engine и Docker Compose v2+**.
Установить pnpm можно командой `npm install --global pnpm@11.25.0`.

Все команды выполняются из корня репозитория. Установите зависимости:

```bash
pnpm install --frozen-lockfile
```

Проектные скиллы, ссылки для агентских клиентов, инструкции и результаты генерации
агентов хранятся в Git и приходят вместе с шаблоном. Отдельная установка скиллов
или подготовительная сборка агентов не требуется. База Relay и подключение к ней
настраиваются отдельно.

Затем запустите инфраструктуру и приложения:

```bash
pnpm infra:dev:up
pnpm backend:prisma:deploy
pnpm dev
```

Первая команда поднимает PostgreSQL, MinIO, RabbitMQ и imgproxy, вторая применяет
миграции к БД. `pnpm dev` запускает сайт, админку, оба API и воркер изображений.
Prisma Client и REST SDK подготавливаются автоматически.

Приложения работают локальными процессами, инфраструктура — в Docker.
При первом запуске собирается образ MinIO, поэтому подготовка может занять несколько минут.

### Интерфейсы и сервисы

Адреса по умолчанию после запуска:

| Сервис                                              | Адрес                        |
| --------------------------------------------------- | ---------------------------- |
| Веб-приложение                                      | <http://localhost:3000>      |
| Админка                                             | <http://localhost:3001>      |
| Client API                                          | <http://localhost:4000>      |
| Swagger Client API                                  | <http://localhost:4000/docs> |
| Admin API                                           | <http://localhost:4001>      |
| Swagger Admin API                                   | <http://localhost:4001/docs> |
| Консоль MinIO — управление S3-хранилищем            | <http://localhost:9001>      |
| S3 API MinIO                                        | <http://localhost:9000>      |
| Панель RabbitMQ                                     | <http://localhost:15672>     |
| RabbitMQ — AMQP                                     | `localhost:5672`             |
| imgproxy — служебный HTTP для обработки изображений | <http://localhost:18080>     |
| PostgreSQL                                          | `localhost:5544`             |

Данные для локальной разработки:

- **Админка:** `admin` / `admin`. Владелец создаётся при первом запуске Admin API,
  если административных аккаунтов ещё нет.
- **MinIO:** `user` / `password`, bucket `default-bucket`.
- **RabbitMQ:** `image` / `image-password`.
- **PostgreSQL:** `user` / `password`, база `default-db`.

Для остановки приложений нажмите `Ctrl+C`, затем выполните `pnpm infra:dev:down`.
Данные Docker volumes сохраняются.

## Настройки окружения

Для стандартного локального запуска достаточно встроенных значений.
Чтобы изменить настройки, скопируйте соответствующий пример в рабочий файл
в том же каталоге и измените значения:

| Пример                                                                       | Рабочий файл |
| ---------------------------------------------------------------------------- | ------------ |
| [`apps/backend/.env.example`](apps/backend/.env.example) | `.env` |
| [`apps/admin/.env.example`](apps/admin/.env.example) | `.env.local` |
| [`apps/web/.env.example`](apps/web/.env.example) | `.env.local` |
| [`infra/dev/.env.example`](infra/dev/.env.example)                           | `.env`       |

Рабочие env-файлы исключены из Git. Их структуру проверяет `pnpm env:check`:
состав и порядок переменных должны совпадать с примером, отличаться могут значения.

## Стенд в Dokploy

**В проекте уже настроен деплой dev-окружения на тестовый стенд в Dokploy.**
Корневой [`docker-compose.yml`](docker-compose.yml) собирает и запускает весь стек.
Для тестового стенда используются production-сборки приложений и простые dev-значения
окружения. Caddy раздаёт админку под `/admin/` и объединяет сайт, оба API и S3
на одном домене по HTTP.

Перед деплоем **агенту и пользователю** прочитать документы в Relay:

| Документ | Что прочитать |
| --- | --- |
| **DOC-18 — Корпоративный dev-стенд в Dokploy** | Основная инструкция: домен, переменные, запуск и проверка стенда. |
| **DOC-4 — Архитектура, приложения и пакеты** | Состав сервисов, их зависимости и маршруты через единый gateway. |
| **DOC-11 — Разработка и локальная инфраструктура** | Настройки окружения, инфраструктура и особенности режима Dokploy. |

Пользователь находит документы в Web-интерфейсе Relay по номеру;
агент читает полный текст через `npx @oim-dev/relay-cli document get DOC-18`
и аналогично для `DOC-4` и `DOC-11`.

Актуальная пошаговая инструкция находится в [`infra/dokploy/README.md`](infra/dokploy/README.md).
Порядок запуска: **домен на `gateway:8080` → всё содержимое
[`infra/dokploy/.env.example`](infra/dokploy/.env.example) в Environment с заменой
`PUBLIC_URL` на выданный HTTP-адрес → Deploy со сборкой**.
После запуска выполнить проверки стенда из инструкции.

## Параллельная работа в worktree

Поддерживаются Linux (с `flock` из util-linux) и macOS (с системными `/usr/bin/perl`
и `/bin/ps`). На macOS инфраструктура запускается через Docker Desktop с Compose v2.

Для отдельной задачи создайте лёгкую рабочую копию:

```bash
pnpm worktree:create task-123
```

Worktree размещается в `~/worktrees/<хост>/<владелец>/<репозиторий>/task-123`.
Создание подготавливает ветку, порты и env, но не вызывает `setup`, не устанавливает
npm-зависимости и не запускает сборки. Проектные скиллы и агентские файлы берутся
из базового Git-коммита без повторной установки или генерации; незакоммиченные изменения
в новую копию не попадают.

Агент сам устанавливает зависимости из каталога созданного worktree.
Менеджер пакетов проекта — pnpm:

```bash
pnpm install --frozen-lockfile
```

Затем из любой рабочей копии этого репозитория запустите окружение:

```bash
pnpm worktree:up task-123
```

`worktree:up` также не устанавливает зависимости автоматически: при отсутствии
`node_modules` он завершится с подсказкой до запуска инфраструктуры.
Порты, четыре env-файла и Docker-ресурсы изолированы. Адреса показывает
`pnpm worktree:status task-123`. Удаление вместе с Docker volumes и рабочими
артефактами: `pnpm worktree:remove task-123`.

Требования, остановка и порядок удаления описаны в Relay: `DOC-14` «Изолированные worktree-окружения».
