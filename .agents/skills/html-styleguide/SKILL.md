# Правила HTML

Применяй к `.html` и HTML-частям шаблонов. Skill определяет оформление и базовую семантику разметки.
Выбор шаблонизатора, структуру приложения и способ создания файлов определяет проект.

## Порядок работы

1. Прочитай инструкции проекта, соседнюю разметку и настройки её проверок.
2. Определи назначение изменяемых элементов и примени правила ниже.
3. Проверь результат по списку в конце и запусти применимые проверки проекта.
4. Если изменилось поведение или семантика, проверь результат в браузере, включая клавиатуру и доступные названия.

## Применение канонов

По умолчанию соблюдай обязательные инструкции, проверки и существующие HTML-соглашения проекта. Правила skill дополняют
неурегулированные решения. Если пользователь или проект явно закрепляет этот канон, применяй его к новой и затронутой
разметке. Незатронутый код не переписывай ради единообразия.

При конфликте канона с обязательными проверками не отключай их и не меняй конфигурацию без разрешения.
Укажи конфликт и запроси решение, если его нельзя разрешить в рамках задачи.

## Форматирование

- Используй 2 пробела и ориентир в 120 символов, если проект не задаёт иное.
- Переноси разметку ради читаемости, а не механического соблюдения лимита.
- Форматируй только затронутый код.

## Элементы и атрибуты

- Теги и атрибуты пиши в нижнем регистре.
- Строковые значения атрибутов пиши в двойных кавычках.
- Статический логический атрибут записывай без значения: `disabled`, а не `disabled="true"`.
- Не добавляй пустые, дублирующиеся и неиспользуемые атрибуты.
- Короткий элемент с небольшим числом атрибутов оставляй в одну строку.
- В многострочном элементе размещай каждый атрибут отдельно.
- Элементы с вложенным содержимым оформляй так, чтобы структура DOM читалась по отступам.

```html
<button
  type="submit"
  name="save"
  disabled
>
  Сохранить
</button>
```

## Семантика

- Используй нативный элемент, соответствующий назначению контента или действия.
- Не добавляй обёртку только ради форматирования.
- Учитывай влияние обёртки на DOM, расположение элементов и доступность.
- Не меняй семантику и ARIA в задаче только на оформление кода.
- При выборе семантического элемента, ARIA и поведения формы отдельно проверь доступность.

## Комментарии

- По умолчанию не комментируй разметку.
- Оставляй комментарий только для внешнего ограничения, обходного решения или неочевидной причины.
- Используй однострочную форму: `<!-- Причина. -->`.
- Не описывай комментариями очевидные секции, если структуру можно выразить элементом или именем шаблона.

## Проверка

- Теги, атрибуты, кавычки и логические атрибуты оформлены единообразно.
- DOM-структура читается по отступам.
- Нет пустых атрибутов и случайных обёрток.
- Семантика не изменена без соответствующей задачи.
- Комментарии объясняют только неочевидные ограничения.
- Обязательные автоматические проверки пройдены.
