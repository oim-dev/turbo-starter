# Локальные шаблоны TSX

Загрузи `template-generation-ru`. Пакет выполняет подстановки и создание файлов; архитектурную форму задаёт приложение.
Обязательная область генерации и системные исключения находятся в [создании TSX](../application/components/tsx-generation.md).

## Настройка нового приложения

1. Установи закреплённую версию генератора и используемый заготовкой `clsx`:

   ```bash
   npm install --save-dev --save-exact @gromlab/template-file-generator@0.3.1
   npm install clsx
   ```

2. Добавь `"create": "template-file-generator --skip-update"` в scripts, сохранив существующие команды.
3. Если локальных шаблонов ещё нет, возьми начальный набор из [assets/templates](../../assets/templates/README.md)
   этого skill и размести его в `.templates/` приложения. Это установка входных шаблонов, а не копирование готового
   прикладного компонента. Существующий набор сначала прочитай и адаптируй, не перезаписывай.
4. Прочитай все файлы выбранного шаблона. Проверь подходящий корневой DOM, правила свойств и импорта CSS.
5. Запускай CLI из каталога приложения: путь вывода не меняет место поиска `.templates/`.

Если приложение использует собственный согласованный помощник классов, адаптируй шаблон до запуска вместо добавления
второго. Другие версии генератора используй по проверенной документации установленного пакета и lock-файлу.

## Выбор и запуск

| Шаблон | Форма |
| --- | --- |
| `ui-component` | Внутренний компонент без фасета |
| `ui-unit` | Самостоятельная визуальная ответственность с начальным `index.ts` |

Например, новый экран и его внутренняя форма:

```bash
npm run create -- ui-unit account src/compositions/screens
npm run create -- ui-component account-form src/compositions/screens/account/ui
```

Каждая команда создаёт папку с переданным именем. Не добавляй это имя повторно к пути вывода.
Это примеры создания ещё не существующих компонентов, а не обновления готовых.

## Адаптация для Next.js

- Шаблоны не добавляют `'use client'` автоматически. Определи среду после выбора поведения.
- Серверному экрану замени начальный `index.ts` на `server.ts` с `import 'server-only'`; клиентскому публичному
  компоненту — на `client.ts` с `'use client'`. Общие типы при реальном потребителе публикуй через отдельный `index.ts`.
- Внутренней форме с хуками добавь `'use client'` в её TSX-файл; собственный фасет ей не нужен.
- Для компонента без DOM удали обёртку, DOM-атрибуты и ненужный CSS. Сохрани собственную папку компонента.
- Для RSC-границы сузь свойства до допустимого контракта; исходный набор DOM-атрибутов рассчитан на использование
  внутри совместимой среды и не разрешает передавать сервером обычные обработчики.
- Замени текст JSDoc назначением и сценариями, удали демонстрационные и неиспользуемые части.
- Не создавай отдельные шаблоны для каждой комбинации server/client/screen/provider, если это только адаптация
  одного каркаса. Для другой реальной файловой формы сначала добавь её локальный шаблон.

После запуска проверь подставленные имена, выбранный фасет, реальные импорты и отсутствие `{{...}}` в прикладном коде.
Результат генератора принадлежит разработчику и не помещается в `generated/`.
