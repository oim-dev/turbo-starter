# SVG-спрайт App Router

Загрузи `svg-sprites-ru` и открой его точное руководство по Next.js App Router для фактического сборщика.
Профильный skill владеет конфигом, CLI и контрактом сгенерированных файлов; здесь закреплено размещение в приложении.

## Настройка

1. Определи владельца набора, например `ui/icons` для общих интерфейсных иконок.
2. Проверь `dev` и `build`: для Turbopack выбери `next@app/turbopack`, для Webpack — `next@app/webpack`.
3. Создай `svg-sprite.config.json` у владельца. Пути `input` считаются от каталога конфига.
4. Закрепи проверенную версию генератора в зависимости разработки и lock-файле либо в команде `npx`.
5. Запускай генерацию до первого процесса, импортирующего `.svg-sprite`, включая проверку типов в чистом CI.
6. Опубликуй компонент и необходимые типы через фасет владельца, не редактируя generated-файлы.

Пример `ui/icons/svg-sprite.config.json` при SVG в соседнем `icons/`:

```json
{
  "mode": "next@app/turbopack",
  "name": "app",
  "input": "./icons/*.svg"
}
```

Имя `app` даёт компонент `AppIcon`; проверь фактические экспорты после генерации.
`ui/icons/index.ts` может явно реэкспортировать его из `./.svg-sprite/index.js`.
Generated-компонент этого режима не требует клиентской директивы и доступен через универсальный фасет.

Если `dev` и `build` используют разные сборщики, согласуй их либо создай отдельную воспроизводимую генерацию для
каждого процесса. Один и тот же результат генерации не считается одновременно выходом двух режимов.

Не переноси сгенерированный `sprite.svg` в `public`, не переписывай его URL и не позволяй собственному SVG-загрузчику
перехватывать этот ресурс. Путь принадлежит адаптеру режима. Viewer добавляй только для реальной визуальной задачи
в отдельной клиентской границе, доступной в разработке.

## Проверка

Запусти генерацию и проверку типов; при настройке режима, URL или сборщика также выполни производственную сборку.
Проверь SSR и клиентский переход, загрузку внешнего SVG, цвет, доступное имя и путь при `basePath`/CDN.
