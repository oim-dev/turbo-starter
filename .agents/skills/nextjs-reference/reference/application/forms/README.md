# Формы

Сохраняй Mantine и `useForm` для интерактивных форм. Приватная форма использует браузерную JWT-сессию и обращается
к backend через операцию домена. Server Action подходит только независимому от этой сессии серверному сценарию.
Если такой сценарий требует отправки до загрузки JavaScript, используй нативную форму с `action`:
это отдельный способ отправки с собственным источником состояния.

## Интерактивная форма

1. Определи владельца сценария. Одноразовая форма экрана остаётся внутренним компонентом экрана; самостоятельный
   предметный визуальный контракт может принадлежать домену.
2. Создай Client Component по [генерации TSX](../components/tsx-generation.md). Для публичной формы передай публичные
   серверные исходные данные. Приватную форму монтируй после подтверждения сессии и получения необходимых
   исходных данных в браузере.
   Операцию JWT-сценария импортируй из `domains/<name>/browser`; `saveAction` от серверного родителя относится только
   к независимому от JWT серверному сценарию.
3. Опиши собственный тип значений формы; не используй DTO и не добавляй служебные поля ввода в предметную модель.
4. Создай `useForm` с `mode: 'uncontrolled'`, полными `initialValues` и `validateInputOnBlur: true`.
5. Поля Mantine получают `key={form.key(path)}` и `form.getInputProps(path)`. Для checkbox укажи `{ type: 'checkbox' }`.
6. Подключи асинхронный обработчик через `form.onSubmit`. Он должен возвращать Promise всего действия, включая
   обработку результата и необходимое клиентское обновление.
7. Используй `form.submitting` для блокировки повторной отправки и состояния кнопки. Не заводи параллельный флаг.

В `uncontrolled` читай актуальные значения из аргумента `onSubmit` или `form.getValues()`. Для отображения, зависящего
от поля, используй поддерживаемую установленной версией подписку, например `form.useWatchValue`; простое чтение
`getValues()` не подписывает компонент.

Клиентская проверка отвечает за удобство ввода: обязательность, длину и формат. Для приватной операции backend
повторно проверяет ввод, JWT и права на действие. Независимая от JWT Action также проверяет вход и ограничения
своего контракта по [правилам записи](../data-fetching/mutations.md).
Не отправляй сетевые запросы из `validate`.

Второй обработчик `form.onSubmit` переводит фокус на первое некорректное поле. Полевая ошибка операции устанавливается
через `setFieldError`, общая ожидаемая ошибка показывается рядом с действием. После ошибки сохраняй введённые значения.
Отклонённый Promise обрабатывай явно; обычная граница ошибок React не ловит все ошибки событий.

## Исходные данные формы

Публичная форма редактирования монтируется с подготовленными на сервере публичными значениями. Используй одинаковую
начальную модель для SSR и браузера. Приватная область сначала показывает общую заглушку, затем загружает данные
в браузере и монтирует форму с полными `initialValues`. Приватные значения не поступают из RSC-свойств.
При переходе к другой сущности или сессии меняй ключ владельца формы, чтобы не оставить прежний черновик.

При браузерной загрузке заблокируй ввод до однократной инициализации. Не вызывай `initialize` или
`setValues` на каждый фоновый ответ: сначала определи правило конфликта с изменёнными полями.

После успеха выполни действие сценария: переход, закрытие либо установку подтверждённых значений как текущих и
исходных с очисткой `dirty`. Не вызывай `reset()` для любой успешной записи автоматически.
Результат старой сессии не меняет форму, кеш и маршрут новой: перед применением проверь поколение сессии.

## Форма с нативной отправкой

Только для независимого от браузерного JWT сценария серверный компонент подключает `<form action={saveAction}>`
с именованными полями `name`, нативными ограничениями и серверной проверкой `FormData`.
Такая форма отправляется до гидратации.

Если нужны результат и ожидание в React, добавь небольшую клиентскую границу с `useActionState`; функция получает
предыдущее состояние и `FormData`. Используй возвращённую Action в `action`, а не вызывай её вне контекста отправки.
Для перехода до гидратации при необходимости задай устойчивый `permalink` и проверь работу на целевом URL.
Кнопка с `useFormStatus` должна быть потомком нужной формы.

В этом режиме значения принадлежат нативным полям, результату Action и выбранному механизму React. Не подключай
`useForm` и второй `onSubmit` к той же форме. У нативной Action-формы успешное завершение может сбрасывать
неконтролируемые поля; явно проверь сохранение ввода при ожидаемой серверной ошибке и восстановление результата.

Не обещай отправку без JavaScript форме, которая работает только через `form.onSubmit` Mantine, восстанавливает
JWT в браузере или редактирует приватные данные. Не добавляй скрытое поле с токеном для серверной отправки.

## Проверка

Публичные исходные значения совпадают при SSR и гидратации; приватная форма появляется только после проверки сессии
и браузерной загрузки. Клавиатура и фокус ошибок работают, повторная отправка блокируется, конфликт сохраняет ввод.
Обновление серверного дерева не стирает активный черновик, выход очищает его, поздний ответ не меняет новую форму.
Для независимой от JWT нативной формы отправка с отключённым JavaScript даёт ожидаемый результат.
