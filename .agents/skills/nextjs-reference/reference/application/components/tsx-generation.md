# Обязательное создание TSX

Новый прикладной `.tsx` создавай через `@gromlab/template-file-generator` из локального шаблона приложения.
Это касается серверных и клиентских компонентов, экранов, каркасов, провайдеров, состояний ошибок, тестов с JSX
и внутренних компонентов без DOM. Ручное копирование соседнего компонента не заменяет запуск CLI.

## Порядок

1. Выбери владельца, среду и нужный публичный фасет.
2. Загрузи `template-generation-ru`, найди `.templates/README.md` и прочитай выбранный шаблон целиком.
3. Если шаблонов нет, выполни [настройку генератора](../../libraries/template-generation.md).
4. Проверь, что целевая папка ещё не существует, и запусти закреплённую команду из корня приложения.
5. Проверь код завершения, пути и подставленные имена.
6. В том же изменении адаптируй свойства, JSDoc, корневой DOM, стиль и фасет; удали ненужные части заготовки.
7. Добавь клиентскую директиву или серверную защиту только по требованиям среды.
8. Подключи реального потребителя и выполни проверки проекта. В результате укажи выполненную команду генерации.

Изменение существующего компонента не требует повторной генерации. Выделение нового при декомпозиции требует.
Не запускай CLI с `--overwrite` для исправления коллизии: сначала проверь существующие и частично созданные файлы.

## Системные исключения Next.js

Без компонентного каркаса можно создать специальные файлы Next.js, когда они только соединяют готовые API:

- `page.tsx` — подготовка параметров, выбор состояния/перехода и подключение публичного экрана;
- `layout.tsx` — обязательные `html`/`body`, CSS, метаданные и подключение публичного каркаса/провайдеров;
- `loading.tsx`, `error.tsx`, `not-found.tsx`, `global-error.tsx`, `template.tsx`, `default.tsx` — адаптация контракта
  фреймворка и подключение готового компонента, включая обязательный документ для `global-error`;
- файл соединения готовых провайдеров без собственного состояния или ресурса.

Исключение определяется ответственностью. Если `page.tsx` начинает реализовывать форму, а `error.tsx` — самостоятельную
визуальную панель, создай эту реализацию генератором у её владельца и оставь специальный файл связующим.
Не добавляй условное исключение для всех файлов в `app`.

Файлы `.templates/` редактируются вручную как вход генератора. Системный результат `create-next-app`, generated REST
и SVG-компоненты создаются собственными инструментами и не перегенерируются шаблонным CLI.
Если нужен новый прикладной TSX другой формы, например изображение метаданных с JSX или тест, сначала добавь
подходящий локальный шаблон. Отсутствие шаблона не разрешает обойти генерацию.
