# SSR, Server Components и гидратация

SSR обязателен для содержимого первого открытия страницы. Это не требует вычислять заново каждую публичную
неизменяемую страницу: предварительное построение и ISR допустимы по [политике кеша](../data-fetching/caching.md).
Персональные данные и данные запроса должны вычисляться в контексте текущего запроса.

## Выбор среды

| Потребность | Решение |
| --- | --- |
| Первоначальные данные, серверные секреты, предметные чтения | Server Component и `domains/<name>/server` |
| Чистая разметка без хуков и специфичных API | Компонент без директив; среда определяется импортирующим графом |
| Состояние, события, `useForm`, SWR, клиентский Context | Небольшая граница `'use client'` |
| DOM, `localStorage`, WebSocket, браузерный SDK | Эффект или событие клиентского компонента с очисткой ресурса |
| SDK, который обращается к DOM уже при импорте | Динамический импорт внутри эффекта; для визуального SDK — отдельная клиентская обёртка с `next/dynamic` |

Server Component может быть `async`; Client Component не объявляй асинхронным. Не добавляй `'use client'` всему
экрану ради одного обработчика. Server Components не используют `useState`, `useEffect`, `useForm` или клиентский Context.

`'use client'` не отключает SSR: код импорта и первоначального отображения выполняется без `window` и `document`.
Проверка `typeof window !== 'undefined'` при отображении не исправляет несовпадение серверного и первого клиентского DOM.

## Передача через границу

Передавай минимальную предметную модель, поддерживаемую сериализацией React. В этом профиле для данных используй
обычные объекты, массивы, примитивы и строки дат с явно заданным часовым поясом. Не передавай токены, полные записи
пользователя, экземпляры клиентов, хранилища состояния, классы ошибок или `Response`.

Обычную функцию и обработчик событий из Server Component передать нельзя. Допустимые отдельные контракты:

- сервером построенный `ReactNode`, переданный в `children` или иной слот;
- ссылка на Server Action в свойстве с именем `*Action`;
- явно спроектированный потоковый сценарий с Promise и React `use`, если он требуется существующему приложению.

Клиентская обёртка не импортирует серверный компонент. Его создаёт серверный родитель и передаёт как содержимое.
Не считай сериализацию фильтром секретов: все переданные свойства могут попасть в ответ браузеру, даже если UI их
не показывает.

## Потоковое отображение

Независимые серверные чтения запускай параллельно. `loading.tsx` покрывает страницу и дочернюю ветку; независимый
медленный блок выделяй под собственный `Suspense` с осмысленным состоянием ожидания.

Чтение должно происходить внутри компонента под границей. `await` в родителе **до** возврата `Suspense` уже блокирует
родителя. Не объединяй быстрый заголовок и медленный необязательный блок в один последовательный запрос без зависимости.

В Server Component не выполняй запись, отправку аналитического события или выход из сессии во время отображения.
Предварительная загрузка маршрута и повторное отображение могут запускать серверное чтение без перехода пользователя.

## Одинаковый первый результат

1. Передай серверные исходные данные клиенту, а не начинай с пустого экрана до эффекта.
2. Используй одинаковые locale, часовой пояс, формат даты и исходную тему на сервере и при гидратации.
3. Не вычисляй время, случайное значение или UUID заново при клиентском отображении; передай значение либо используй `useId`
   для связей элементов формы.
4. Для адаптивности используй CSS, а не выбор первого JSX по ширине окна.
5. Сохранённые браузерные настройки применяй после монтирования к согласованному начальному состоянию.
6. Соблюдай HTML-вложенность: автоматическое исправление браузером неправильного DOM ломает гидратацию.

`suppressHydrationWarning` допускается только для известного точечного отличия, например интеграции темы Mantine по
её инструкции. Не добавляй его на дерево приложения для сокрытия расхождений.

`dynamic(..., { ssr: false })` используй только внутри Client Component для действительно несовместимого с SSR
виджета. Выдели ему устойчивый заполнитель; остальная страница и её основные данные продолжают отображаться на сервере.
Не применяй этот приём к страницам, формам и Mantine ради устранения ошибки импорта.

## Проверка

Проверь HTML прямого запроса и страницу с отключённым JavaScript, затем гидратацию с JavaScript, клиентский переход
и перезагрузку. Для потока дождись окончания ответа: первый фрагмент закономерно может содержать состояние ожидания.
Отсутствие интерактивности без JavaScript допустимо; отсутствие всего содержимого страницы — нет.
