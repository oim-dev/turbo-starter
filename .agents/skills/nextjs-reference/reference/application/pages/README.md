# Создание страницы

Страница Next.js состоит из обязательной точки входа маршрута и принадлежащего композиции экрана.
`page.tsx` адаптирует URL и соединяет публичные API; экран владеет разметкой и пользовательским сценарием.

## Порядок

1. Определи путь, параметры, публичное содержимое, приватные блоки и ожидаемый результат отсутствия сущности.
2. Для публичных данных найди доменный серверный API, для приватных — браузерную операцию и клиентский хук по
   [получению данных](../data-fetching/README.md).
3. Создай экран через CLI в `compositions/screens/<name>`. Выбери серверный фасет, если экран выполняет серверные
   чтения или использует серверные зависимости; чистый универсальный экран может иметь `index.ts`.
4. Создай специальный `app/<путь>/page.tsx` по [исключениям генерации](../components/tsx-generation.md).
5. Дождись `params` и `searchParams`, проверь входные значения и передай подготовленные параметры экрану.
6. Выдели интерактивность и приватные блоки в клиентские компоненты экрана. Server Actions передавай как `*Action`
   только для независимых от браузерного JWT сценариев; приватная запись использует браузерный доменный API.
7. Добавь необходимые `loading.tsx`, `error.tsx`, `not-found.tsx` и метаданные.
8. Проверь прямой URL, переход, обновление, отсутствие данных и отправку действия.

## Точка входа

Фрагмент `app/catalog/[slug]/page.tsx` предполагает опубликованный серверный `ProductScreen`:

```tsx
import type { ReactNode } from 'react'
import { ProductScreen } from 'compositions/screens/product/server'

/**
 * Соединяет маршрут каталога с экраном товара.
 *
 * Используется для:
 *  - открытия товара по параметру URL
 */
export default async function Page(props: PageProps<'/catalog/[slug]'>): Promise<ReactNode> {
  const { slug } = await props.params

  return <ProductScreen slug={slug} />
}
```

`PageProps` генерируется Next.js командой `next typegen`, `next dev` или `next build`. Наличие типа не проверяет
корректность значения по предметным правилам: доменная операция проверяет допустимый slug и существование товара.

`searchParams` может содержать строку, массив строк или отсутствие значения. Явно нормализуй страницу, фильтр,
сортировку и повторяющиеся параметры. Не приводи их через `as` к желаемому типу.

Публичное серверное чтение остаётся в экране либо точке входа, когда результат определяет маршрут. Не запускай
одинаковое чтение ещё раз в клиентском эффекте. Приватная область получает только публичные параметры ресурса,
показывает начальную заглушку и загружает данные после браузерной проверки сессии.
Серверная страница не проверяет браузерный JWT и не передаёт приватные данные через свойства.
Потоковые границы размещай по [SSR](../rendering/README.md).

## Метаданные

- Для постоянных значений экспортируй `metadata`; для данных маршрута — `generateMetadata`.
- Эти экспорты остаются на сервере в специальных файлах Next.js, а не в Client Component.
- Динамические метаданные получают только публичные данные через ту же доменную операцию, что и публичный экран.
  При повторном чтении используй дедупликацию текущего отображения по [кешированию](../data-fetching/caching.md).
- Публичный базовый URL, canonical, Open Graph и индексирование задай из настроек приложения и требований страницы.
- Не помещай приватные данные в заголовок, описание или изображение только потому, что запрос выполняется на сервере.
- `generateStaticParams` добавляй лишь для намеренно предварительно строящегося набора публичных путей. Определи
  поведение неизвестных параметров и обновление списка; функция не запускается заново при каждом ISR-обновлении.

## Состояния

`loading.tsx` показывает ожидание ветки, `not-found.tsx` — предусмотренное отсутствие, `error.tsx` — сбой её
отображения. Реализация этих состояний принадлежит композиции или универсальному UI и создаётся генератором.
Специальные файлы подключают её по контракту Next.js. Не добавляй каждый файл, если сценарий его не требует.

`error.tsx` — Client Component. Он не ловит ошибку собственного layout; такую ошибку перехватывает родительская
граница. Для корневого layout используется `global-error.tsx` со своими `<html>` и `<body>`.

Статус ответа после начала потока уже нельзя свободно изменить: отсутствие данных, найденное поздно, может
показывать правильный UI при HTTP 200. Если нужен строгий HTTP 404/redirect до потока, выполни соответствующее
решение до начала отправки тела и проверь статус реальным запросом. Это относится к публичным серверным данным;
отказ доступа и отсутствие приватной сущности обрабатываются клиентской областью после ответа backend.
