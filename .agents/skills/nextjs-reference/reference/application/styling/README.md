# Стили

Используй CSS Modules с PostCSS и загрузи `postcss-styleguide`. Общая обработка настраивается по
[инструкции PostCSS](../../libraries/postcss.md), тема — по [Mantine](../../libraries/mantine.md).

- CSS Module принадлежит владельцу DOM и не импортируется другим юнитом.
- Общая тема, переменные и контрольные точки находятся в `ui/themes`.
- Публичный `ui/themes/styles.css` является явной точкой подключения глобальных стилей. Это ресурс юнита,
  а не маркер нового юнита и не разрешение на глубокий импорт его внутренних файлов.
- Корневой `app/layout.tsx` подключает CSS Mantine, установленных расширений и затем `ui/themes/styles.css` ровно один раз.
- В клиентском ThemeProvider не дублируй эти импорты.

Сначала используй свойства Mantine, затем `classNames`/`className` и его публичные CSS-переменные.
Не обращайся к сгенерированным именам классов и внутренней DOM-структуре библиотеки.

Функции в `styles`, `vars`, `render*` и других свойствах создавай в клиентской реализации; их нельзя передавать как
обычные функции из Server Component. Статические строки классов и сериализуемые параметры можно передавать с сервера.

Адаптивность и первоначальную тему выражай CSS и согласованной настройкой темы. Чтение ширины окна при отображении не
заменяет медиавыражения и нарушает одинаковый первый результат SSR. Не скрывай всё приложение до монтирования.

При изменении сборки CSS проверь производственный результат, порядок слоёв/импортов, вложенность, `@custom-media`
и отображение после перехода между маршрутами. Наличие стилей в `next dev` не доказывает правильный порядок в сборке.
