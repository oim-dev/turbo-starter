# Платформа Next.js

## Версии и запуск

Для нового приложения используй стабильную исправленную версию Next.js 16, совместимую React 19 и поддерживаемый
Node.js LTS. Закрепи версии и пакетный менеджер lock-файлом. Минимум Node.js для Next.js 16 — 20.9, но минимальная
версия не является рекомендацией использовать завершившую поддержку ветку.

Сохраняй инструкции существующего проекта. При работе с новой версией сначала прочитай её документацию, включая
доступную в `node_modules/next/dist/docs/`; не применяй автоматически старый синхронный контракт Request APIs.

Базовые команды пакета приложения:

```json
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start",
    "typecheck": "next typegen && tsc --noEmit",
    "lint": "eslint .",
    "create": "template-file-generator --skip-update"
  }
}
```

Эти команды предполагают установленные Next.js, TypeScript, ESLint с совместимой конфигурацией Next.js и генератор.
`next lint` в Next.js 16 отсутствует, а `next build` не заменяет линтер. Сохраняй имеющиеся проверки и хуки генерации.
Настройку генератора выполняй по [его инструкции](../../libraries/template-generation.md).

Новый профиль использует Turbopack для обеих команд. Если проекту нужен Webpack, явно согласуй `next dev --webpack`
и `next build --webpack`, плагины и режим SVG. Не оставляй рабочую настройку только для одного сборщика.

Минимальный `next.config.ts` профиля:

```ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: false
}

export default nextConfig
```

Выбор модели объяснён в [кешировании](../data-fetching/caching.md). Не добавляй экспериментальные параметры,
`output: 'export'` и React Compiler без соответствующей задачи.

## TypeScript и алиасы

Сохрани настройки Next.js, его TypeScript plugin, `next-env.d.ts`, include генерируемых типов и
`moduleResolution: 'bundler'`. Не заменяй tsconfig полным чужим примером ради алиасов.

Добавь к существующему `compilerOptions.paths`:

```json
{
  "app/*": ["./src/app/*"],
  "compositions/*": ["./src/compositions/*"],
  "domains/*": ["./src/domains/*"],
  "infra/*": ["./src/infra/*"],
  "ui/*": ["./src/ui/*"],
  "shared/*": ["./src/shared/*"]
}
```

Next.js понимает `paths`; ручной дубликат настройки Vite не нужен. Отдельный тестовый процесс настраивается на те же
алиасы. `PageProps`, `LayoutProps` и `RouteContext` появляются после генерации типов, поэтому чистая проверка типов
сначала выполняет `next typegen`.

`cookies()`, `headers()`, `draftMode()`, `params` и `searchParams` используй по асинхронному контракту Next.js 16.
Не приводи Promise к синхронному значению. В Client Component предпочитай готовые подготовленные свойства;
если проект использует передачу Promise, разворачивай её поддерживаемым React API.

## Окружение

Серверную конфигурацию размести в `infra/environment` и публикуй через `server.ts` с `server-only`.
Проверь обязательные значения до использования и возвращай понятную диагностическую ошибку без значений секретов.

- `process.env` используется вместо `import.meta.env` и префикса `VITE_`.
- `NEXT_PUBLIC_*` доступно браузеру и обычно встраивается при сборке. Здесь нельзя хранить секреты или менять настройки
  одного артефакта между окружениями без новой сборки.
- Для настройки времени выполнения прочитай серверное значение при обработке запроса и передай клиенту только
  разрешённый сериализуемый набор. При необходимости отложи чтение через `connection()`.
- В `.env.example` храни имена и безопасные описания. Реальные `.env.local` и данные авторизации не коммить.
- Внутренний URL API не собирай из произвольного `Host` входящего запроса. Используй доверенную конфигурацию.

## Изображения, шрифты и локализация

Статические файлы публикуются из `public`; не импортируй их через Vite-специфичные суффиксы.
Изображения содержимого подключай через `next/image`, указывай размеры или контейнер для `fill`, корректные `sizes`
и доступный `alt`. Разрешённые внешние источники задавай узко в `images.remotePatterns`.

Используй `next/font` при подключении шрифта. Для воспроизводимой сборки без внешней сети предпочитай проектные
файлы и `next/font/local`, если шрифт доступен проекту. CSS-переменную шрифта согласуй с темой Mantine.

Locale и часовой пояс должны быть явными и одинаковыми при SSR и гидратации. Для форматирования достаточно `Intl`;
при уже принятом Day.js сохрани его и настрой плагины у владельца. Не выбирай язык первого отображения по `navigator`.
Если есть локализованные маршруты, нормализуй locale в границе URL и загружай нужные словари на сервере; клиенту
передавай только используемые сообщения. Новую библиотеку локализации без требования не добавляй.

## Развёртывание

SSR, Server Actions, приватные cookie и Route Handlers требуют серверной среды Next.js. Используй `next build`
и `next start` либо согласованный серверный адаптер платформы. Статический экспорт не является реализацией этого профиля.

По умолчанию используй среду выполнения Node.js. Edge выбирай только при подтверждённой совместимости всех зависимостей и
требовании среды. Если нужен standalone-артефакт, проверь доставку `public` и `.next/static` вместе с сервером:
их наличие в выходе не предполагается автоматически.

При нескольких экземплярах согласуй хранение кеша, доставку его актуализации, версию сборки и параметры Server Actions.
Локальная память процесса не является общим долговременным хранилищем. Проверь размеры и длительность запросов,
загрузку файлов и поддержку потокового ответа на реальном прокси/платформе.
