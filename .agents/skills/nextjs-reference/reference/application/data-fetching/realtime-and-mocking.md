# Подписки и имитация API

## Данные в реальном времени

Первоначальный публичный снимок восстановимых данных получай на сервере. Приватный снимок загружается только браузером
после подтверждения JWT-сессии. Клиентский владелец подключает WebSocket, SSE или SDK через браузерный API
инфраструктурного юнита после монтирования; приватная подписка также ожидает подтверждения сессии.
Не создавай соединение во время SSR или на уровне модуля.

- Транспорт отвечает за протокол, соединение, отключение и повторное подключение.
- Домен преобразует сообщения в предметные события и определяет порядок их применения.
- Для последнего временного значения используй `useSWRSubscription` при уже принятом SWR.
- Для событий, обновляющих REST-состояние, обновляй тот же GET-кеш либо запускай повторное чтение.
- Если важно обработать каждое событие, используй очередь или reducer владельца; кеш последнего значения не сохраняет
  историю и не гарантирует обработку всех сообщений.

Определи, как закрывается промежуток между серверным снимком и подключением: версия/курсор из контракта либо
повторный GET после установки подписки. После восстановления связи также сверяй состояние с источником.
Возвращай очистку из эффекта или подписки; смена пользователя закрывает старое соединение и его обработчики.
Поздние сообщения завершённого поколения сессии не изменяют новое. Авторизация соединения следует контракту backend;
не передавай JWT в URL и не предполагай, что браузерный WebSocket или `EventSource` поддерживает произвольные заголовки.

Не размещай долгоживущий WebSocket-сервер в Route Handler без подтверждённой поддержки среды развёртывания.
При передаче SSE через HTTP-обработчик проверь отмену, длительность запроса, буферизацию прокси и лимиты платформы.

## Автономная разработка и тесты

Браузерный worker MSW не видит запросы, которые Server Components выполняют в процессе Next.js.

Для сквозного локального сценария с SSR используй отдельный имитирующий HTTP-сервис с согласованными фикстурами
и направь на него серверный API URL. Это воспроизводит реальную транспортную границу и работает при `next build`
и `next start`. Если публичные данные строятся при сборке, сервис должен быть доступен уже на этом этапе.

Для изолированных тестов адаптера допустим MSW в Node.js. Инициализируй и очищай его средствами тестового процесса;
не предполагай, что этот перехват автоматически действует в отдельно запущенном Next.js.
Клиентские запросы при необходимости проверяй отдельно с браузерным MSW.

Фикстуры отражают реальный контракт, включая предусмотренные ошибки. Не подменяй неизвестный API вымышленной схемой.
Локальный флаг имитации не публикуй как секрет и не включай имитацию в рабочее развёртывание.

Проверь первоначальный серверный HTML, клиентское обновление, запись и повторное чтение одним сценарием.
