# Server Actions и Route Handlers

Выбирай границу по потребителю:

- действие интерфейса этого Next.js-приложения выполняется через Server Action;
- браузерный GET, webhook, скачивание, поток и внешний HTTP-потребитель используют Route Handler;
- Server Component вызывает серверный API домена напрямую;
- уже согласованный прямой браузерный API сохраняется без дублирующего обработчика Next.js.

Не используй Server Actions как GET-загрузчики SWR: это удалённые вызовы через POST с собственной моделью выполнения.

## Размещение Server Action

Связующая Action находится в `app/<ветка>/actions.ts` с директивой `'use server'`. В файле экспортируются только
асинхронные действия. Типы результатов, схемы и константы принадлежат своим владельцам и не экспортируются из него.

Action адаптирует внешний ввод, вызывает серверную операцию домена, актуализирует нужный кеш и при необходимости
выполняет переход. Она не реализует предметные правила и не создаёт HTTP-клиент. Для повторяющегося предметного
процесса расширь доменную операцию, а не копируй его между Actions.

Серверный `page.tsx` импортирует Action внутри `app` и передаёт её экрану или форме как `saveAction`.
Это ссылка на удалённый вызов, а не обычная функция, захватывающая серверный клиент. Клиентские юниты не импортируют
`app`; фасет `server.ts` также нельзя импортировать в клиентскую форму ради Action.

## Порядок выполнения

1. Прими вход как недоверенное значение. Проверь `FormData` или объект во время выполнения; тип TypeScript и `bind`
   не доказывают корректность и не дают прав доступа.
2. Получи текущую сессию на сервере. Проверь разрешение на конкретную операцию и конкретный объект в доменном API.
3. Выполни запись через существующий доменный адаптер. Не доверяй переданным `userId`, цене, роли или владельцу записи.
4. Подготовь предусмотренный результат как сериализуемое объединение с признаком, например `status`.
5. После успеха актуализируй нужные данные по [правилам кеша](caching.md).
6. Заверши сценарий возвратом результата либо `redirect`. Помести `redirect` вне `try/catch`, перехватывающего ошибки записи.

Ожидаемые исходы могут выглядеть как `success`, `validation-error`, `conflict`, `unauthenticated`, `forbidden`.
Состав определяется операцией, а не универсальным списком для всех форм. Результат ошибки содержит безопасные коды
и сообщения, а не `Error`, DTO, стек или технический ответ API.

Неожиданный сбой логируется на сервере и выбрасывается в канал ошибки Next.js; клиент не пытается восстановить
предметный исход из сокращённого серверного исключения. Подробнее — [качество](../quality/README.md).

При обработке двойного нажатия блокируй повторную отправку в интерфейсе. Если последствия требуют гарантии от
повторной записи, используй идемпотентность по контракту сервера: клиентская блокировка её не обеспечивает.

## Route Handler

Размещай обработчик в `app/api/<ресурс>/route.ts`. Экспортируй нужные методы `GET`, `POST` и другие именованными
функциями. В одном сегменте не совмещай `page.tsx` и `route.ts`.

Обработчик владеет HTTP-границей:

1. Разбирает URL, асинхронные `params`, заголовки и тело.
2. Проверяет вход, сессию и допустимость вызова; предметные права проверяются серверной операцией.
3. Вызывает домен и преобразует предусмотренный результат в статус и безопасный ответ.
4. Задаёт явный `Cache-Control`: для персонального ответа — `private, no-store`.
5. Обрабатывает неожиданный сбой в серверной диагностике и возвращает безопасный 5xx.

Для новых cookie-аутентифицированных изменяющих Route Handlers определи защиту от межсайтовой отправки: проверку
`Origin` по разрешённым адресам приложения и CSRF-механизм, если он требуется контрактом. Встроенные проверки
Server Actions не распространяются автоматически на произвольный `route.ts`.

Webhook проверяет подпись и защиту от повторной обработки по контракту источника, а не браузерную сессию.
Не выполняй запись через GET. Не проксируй произвольный URL, все входные заголовки или все cookie.

Серверный `fetch` не отправляет браузеру полученный от внешнего API `Set-Cookie`. Вход и обновление сессии должны
явно установить cookie ответа Next.js в Action или Route Handler по [правилам авторизации](../authentication/README.md).

## Проверка

Вызови обработчик напрямую без UI, с отсутствующей сессией, неверным вводом и чужим идентификатором. Затем проверь
успешную запись, ожидаемый конфликт, повторную отправку, актуализацию экрана и отсутствие записи при обычном отображении.
