# Генерация компонентов Next Web App

Шаблоны основаны на React Reference и применяются в рамках [профиля приложения](../AGENTS.md#архитектурный-профиль).
Перед генерацией определите владельца и необходимость отдельного публичного контракта.

| Шаблон | Результат |
| --- | --- |
| `ui-component` | Внутренний компонент со своей папкой, типом props и CSS Module, без фасета |
| `ui-unit` | Компонент-юнит с той же структурой и публичным `index.ts` |

Запускать из `apps/next-web-app` только для нового имени и отсутствующей целевой папки:

```bash
PNPM_CONFIG_VERIFY_DEPS_BEFORE_RUN=false pnpm run create ui-unit welcome src/compositions/screens
PNPM_CONFIG_VERIFY_DEPS_BEFORE_RUN=false pnpm run create ui-component welcome-note src/compositions/screens/welcome/ui
```

Примеры предназначены для ещё не существующих компонентов. Позиционный путь задаёт родительскую папку вывода;
папку компонента создаёт CLI. Команда закрепляет `@gromlab/template-file-generator@0.3.1`
и отключает проверку обновления. Перед генерацией прочитайте
[template-generation](../../../.agents/skills/template-generation/SKILL.md) и выбранный шаблон.
Повторная генерация поверх существующего результата запрещена; редактируйте созданный код обычным способом.

После генерации:

1. Для экрана используйте `<name>.screen.tsx`, для каркаса — `<name>.layout.tsx`; согласуйте имена компонента и props.
2. Замените JSDoc назначением и реальными сценариями применения.
3. Экраны всегда сохраняют полный каркас: параметр `props`, отдельный файл типов, CSS Module и фасет с типом props.
   Если собственных параметров нет, используйте `ScreenParams = object`, `RootAttrs` и `ScreenProps`.
   Разрешённые атрибуты и `className` передаются корневому элементу экрана.
4. У остальных компонентов адаптируйте типы и стили по реальному контракту; у компонента без DOM удалите `RootAttrs` и обёртку.
5. Оставьте в фасете только API для фактических потребителей. Клиентский API публикуйте через `client.ts` по профилю.
6. Проверьте результат через lint, check-types и build приложения.

Шаблоны создают совместимый с SSR каркас без автоматической клиентской директивы.
Framework-файл `page.tsx` подключает экран с явно выбранными props, чтобы служебные параметры Next.js не попадали в DOM.
Зависимости: React, `clsx`, CSS Modules. `index.ts` объявляет юнит, а не локальный barrel.
Конфигурационные исходники `.templates` исключены из обычного TypeScript/ESLint-прохода;
при изменении обоих шаблонов проверяйте их пробную генерацию и типы результата в окружении приложения.
