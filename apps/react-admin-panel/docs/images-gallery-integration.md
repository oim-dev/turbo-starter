# Галерея изображений

## Владельцы

- `src/domains/images` — самостоятельный сквозной домен: модели, runtime-проверки,
  классификация, адаптеры generated SDK, SWR и визуальный контракт `ImagePreview`.
- `src/compositions/screens/images` — экран `/images`, папки, мобильный drawer,
  поиск и фильтры, пагинация, карточки, паспорт изображения и очередь загрузки.
- `src/infra/backend-admin-api` — единственный настроенный административный
  транспорт; необходимые generated DTO публикуются его фасетом.
- `src/infra/presigned-upload` — XHR PUT с прогрессом и отменой, без cookie/JWT.
- `src/infra/file-digest` — чтение исходных байтов через FileReader и SHA-256
  через WebCrypto. Фасет публикует `computeFileSha256` и техническую ошибку;
  единственный потребитель — домен `images`. Предметных моделей и транспорта здесь нет.
- `src/infra/native-file-drop` — нативные события переноса файлов документа;
  публичный `useNativeFileDrop` подключается страницей и открытым загрузчиком
  взаимно исключительно. Проверка прав и пользовательские сообщения остаются в композициях.
- `app/router` подключает экран через `PermissionBoundary`. Основное меню и
  действия используют серверный снимок прав auth-домена.

## Данные и жизненный цикл

Операции используют реальные методы группы `backendAdminApi.images`.
Модели SDK не выходят из адаптеров в UI. Runtime-проверки выполняются до записи
в кеш. Terminal 401 передаётся auth-владельцу вместе с отклонённым credential.

Ключи запросов имеют форму `['private', userId, 'images/<resource>', ...args]`.
Дополнительную изоляцию сессий обеспечивает существующий `AuthProvider`.
Список получает все фильтры и страницу в ключе; detail и facets имеют свои GET-ключи.
Единственный polling списка активен при queued/processing на странице, в
открытых подробностях или среди собственных подтверждённых upload/retry.
`useImageActions` владеет локальным набором pending-ID, привязанным к текущей
identity. Это данные наблюдения за действием, а не копия серверных моделей.
При смене сессии дерево `AuthProvider` пересоздаёт scope; чужие ID не попадают
в новое наблюдение и cache refresh ограничен текущим userId.

Перед каждым чтением списка доменный hook получает свежие модели наблюдаемых ID
через обычный GET-adapter, группами максимум по четыре одновременных запроса.
Метаданные читаются **перед** списком: когда задача стала ready, следующий GET
уже может включить её в ready-фильтр. Подробности синхронизируются даже для ID,
которого больше нет на странице. После ready/failed ID удаляется из наблюдения,
а список и фасеты обновляются. Закрытие upload-modal или details не сбрасывает
наблюдение за собственными заданиями.

Каждый запуск fetcher увеличивает generation-счётчик владельца. Завершившийся
устаревший запрос может вернуть результат своему SWR-ключу, но не синхронизирует
подробности и не удаляет pending-ID. Generation проверяется после GET списка,
в callback обновления кеша и повторно перед завершением наблюдения. Дополнительно
запоздавший снимок не заменяет модель с более новым `updatedAt`. Повторный GET
активного списка изнутри его fetcher не запускается.

Интервал — 2500 мс, новая итерация ожидает завершения предыдущего GET-цикла.
После завершения всех наблюдаемых заданий и отсутствия других pending он равен
нулю. Таймеров плиток нет. Скрытая/offline-вкладка не опрашивается; ошибка GET
останавливает polling, автоматический retry ошибки отключён. Повторное чтение
возможно по явному обновлению, восстановлению сети или фокусу.

Изменяющие adapters не зависят от SWR. `useImageActions` обновляет активные
GET-запросы после подтверждённой записи. До create вычисляется SHA-256 исходных
байтов, не имени или размера файла. Создание загрузки не повторяется автоматически:
проверка → create → presigned PUT с server-provided headers → complete.
Если create возвращает существующее изображение, PUT и complete не выполняются.
`uploadImage` возвращает предметный результат `{ image, isReused }`, а прогресс —
`{ phase, percent }`: `checking`, `uploading`, `confirming`. Процент отражает
передачу байтов; у чтения, хеширования и подтверждения нет вымышленного процента.

Complete может разрешить гонку в пользу другого изображения. `useImageActions`
наблюдает и обновляет detail-кеш по **итоговому** `image.id`, защищая более свежий
`updatedAt`. Список и фасеты перечитываются с сервера, локального добавления
дублирующей карточки нет. Повторные pending-ID схлопываются.

Обработка продолжается в фоне, локальная очередь показывает `done` для новых
файлов и `reused` («Уже есть в медиатеке») для существующих, включая дедуп при
complete. Итоги новых и reused считаются отдельно. После завершения активной
операции из строки можно открыть подробности канонического изображения.
Папка и теги формы применяются только к новым изображениям; существующая
классификация, название и автор сохраняются.

«Остановить загрузку» прерывает текущую операцию и сохраняет ожидающие файлы.
Чтение FileReader действительно останавливается, подписки очищаются. WebCrypto
не поддерживает остановку digest: отмена немедленно завершает ожидание, поздний
результат игнорируется, create после отмены не отправляется. Нужен secure context
(HTTPS или localhost) и WebCrypto. Проверка выполняется только для непустых
JPEG/PNG/WebP до 20 МиБ; отсутствие WebCrypto, ошибка чтения и серверный
`IMAGE_HASH_MISMATCH` отображаются как восстанавливаемые ошибки файла.
Поздний XHR progress после отмены не передаётся в UI: он не может заменить
`cancelled` на `uploading` и скрыть кнопку возврата в очередь.
«Вернуть в очередь» подготавливает явную новую попытку без повторного выбора файла;
папка и теги остаются в форме.
Object URL создаются эффектом строки очереди и освобождаются при удалении файла
и размонтировании формы. Инициализация очереди не создаёт browser-ресурсов;
повтор эффектов StrictMode не дублирует файлы и не оставляет активных URL.

### Wire contract

- `ImageDto.id` остаётся UUID. `publicId` — обязательная строка из восьми символов
  base62; `original.sha256` — обязательное поле, `null` либо 64 lowercase hex.
  Старый оригинал с `sha256: null` остаётся доступен для просмотра.
- `CreateImageUploadDto.sha256` опционален для API, но SPA всегда передаёт
  вычисленный lowercase SHA-256 до первого POST.
- Create возвращает `{ image, reused, upload }`. `reused` строго boolean;
  `true` требует `upload: null`, подтверждённого SHA-256 и завершённой передачи
  канонического оригинала. `false` требует состояния `uploading` и валидной цели PUT.
- Complete возвращает **плоский** `ImageDto` с `reused: boolean`. Mapper проверяет
  подтверждённый SHA-256; для `reused: false` ID обязан совпасть с ID созданной загрузки.
- GET/retry возвращают обычный `ImageDto`. Новые поля и сочетания проверяются
  во время выполнения до попадания в модель, кеш и UI. Неизвестный ответ записи
  остаётся application defect, а не маскируется под успешный upload.

## Перетаскивание файлов

Страница передаёт первую `NativeFileDrop` пачку через `initialBatch` во вложенный
`ImageUpload`. Это одноразовый входной контракт; единственная изменяемая очередь,
классификация, передача и отмена принадлежат загрузчику. Открытая форма принимает
последующие drop напрямую своим экземпляром `useNativeFileDrop`, не обращаясь к
родителю или соседним юнитам. Нет event bus и императивного доступа к очереди.

На `dragenter`/`dragover` проверяется `DataTransfer.types` (`Files`), а не `files`:
в protected mode список файлов пуст. Чтение `items/getAsFile` и каталогов выполняется
синхронно только на `drop`. Текст и URL не открывают форму; `dragstart` из документа
отличает перенос существующей картинки от OS-файла. Файловая навигация браузера
предотвращается, включая неподдерживаемые файлы и отсутствие `images.upload`.

Подсветка учитывает вложенные enter/leave и очищается при выходе, drop, Escape,
dragend и потере фокуса окна. Native document listener не удваивается React-порталом.
Без права загрузки видны объяснение и запрещённый курсор; форма не открывается.
Непустые JPEG/PNG/WebP из смешанной пачки добавляются, неподходящие и пустые файлы
получают пояснение. Ошибка декодирования локального превью отображается в строке
файла; содержимое окончательно проверяется сервером. Каталоги не обходятся рекурсивно. Во время активной передачи
добавление заблокировано с подсказкой дождаться завершения или остановить загрузку.
Закрытие idle-формы не запускает загрузку автоматически.

Поведение соответствует MDN:
[DataTransfer.files](https://developer.mozilla.org/en-US/docs/Web/API/DataTransfer/files),
[File drag and drop](https://developer.mozilla.org/en-US/docs/Web/API/HTML_Drag_and_Drop_API/File_drag_and_drop).

Original скачивается через защищённую SDK-операцию `{ url, expiresAt }`;
временная ссылка проверяется, не сохраняется в SWR и не используется для превью.
`UPLOAD_EXPIRED` означает необходимость новой загрузки: повтор задания и
скачивание отсутствующего оригинала не предлагаются. Для повреждённых исходников
поясняется, что повтор обработки не исправляет байты.

## Отображение

`@unpic/react/base` использует custom transformer только по полному ready-манифесту.
`getImageFormatGroups` группирует реальные файлы манифеста по расширению,
`getImagePreviewVariants` выбирает одну опубликованную группу. Все `srcset`
содержат фактически существующие ширины; `picture` предпочитает AVIF
и использует опубликованный JPEG/PNG fallback. Пропорции берутся из готового
варианта, не из метаданных приватного оригинала. Это также сохраняет корректность
старого однородного манифеста, выбранного сервером. Обработка не запускается GET-запросами.
Заглушка принадлежит UI. После ошибки превью доступен явный повтор загрузки;
новое изображение не наследует ошибку предыдущего.

Новая обработка сохраняет исходные пропорции, использует шаг 200 px и предел
2000 px без увеличения. Максимальная ширина включается с зазором не менее 100 px
до предыдущего размера: например, 810 → 200/400/600/810. Расчёт принадлежит серверу;
frontend не достраивает размеры и URL самостоятельно. Контракты загрузки, изображения
и варианта не содержат выбора кадрирования.

В подробностях Mantine Tabs формируются только по форматам манифеста: например,
AVIF/PNG или AVIF/JPEG. Внутри — все фактические размеры по возрастанию ширины,
вес, открытие и копирование URL. Таблица умещается на 390 px без горизонтальной
прокрутки; вкладки доступны с клавиатуры. Активный формат сохраняется при обновлении
того же изображения, при смене изображения выбирается первый существующий формат.
Короткий ID показан в паспорте с отдельной кнопкой копирования; UUID остаётся
системным ID. Таблица сохраняет компактность: одна строка на вариант с размерами,
весом и кнопками открытия/копирования. Полные URL не выводятся отдельным текстом
ни в паспорте, ни под строками таблицы; адрес доступен через знакомые действия.
Новые адреса имеют вид `/media/images/:publicId/:format/:widthxheight`, но frontend
берёт их **только** из `variants[].url`: не строит маршрут, формат и размеры сам.
Поле поиска подсказывает «Имя, ID или URL изображения» и передаёт исходную строку
после удаления крайних пробелов в backend. Извлечение ID из URL и поиск принадлежат
серверу; выбранные фильтры папки, тега и статуса продолжают действовать.

Папки используют единый однострочный layout, ellipsis, полную hover/focus-подсказку
и несжимаемый счётчик.

Папка — одна строка-путь, теги — свободный нормализуемый набор. Формы Mantine
работают в uncontrolled-режиме. Ошибка сохранения или revalidation не размонтирует
уже открытую форму и не заменяет dirty-ввод. Папки являются настоящими кнопками,
drawer/modal удерживают фокус, действия имеют доступные названия.
Возврат фокуса принадлежит экрану через Mantine `useFocusReturn`: экран переживает
размонтирование очереди и подробностей, включая переход из reused-результата.
Текст исходов, ошибок и кнопки остановки использует контрастные токены темы.

## Генерация TSX

Все новые TSX созданы `pnpm run create` из приложения:

```text
ui-unit images src/compositions/screens
ui-unit image-folders src/compositions/screens/images/ui
ui-unit image-grid src/compositions/screens/images/ui
ui-unit image-details src/compositions/screens/images/ui
ui-unit image-upload src/compositions/screens/images/ui
ui-component image-card src/compositions/screens/images/ui/image-grid/ui
ui-component image-classification src/compositions/screens/images/ui/image-details/ui
ui-component image-variants src/compositions/screens/images/ui/image-details/ui
ui-component upload-file src/compositions/screens/images/ui/image-upload/ui
ui-component image-preview src/domains/application/images/ui
```

`images.tsx` адаптирован в `images.screen.tsx`. После уточнения владельца весь
новый домен вместе с `image-preview` перенесён в `src/domains/images`.
`--overwrite` не использовался. На этапе подключения SDK новых TSX не потребовалось.

Для этапа DnD и вкладок через `pnpm run create` созданы внутренние компоненты:

```text
ui-component image-drop-overlay src/compositions/screens/images/ui
ui-component image-format-files src/compositions/screens/images/ui/image-details/ui/image-variants/ui
```

Для SHA-256, короткого ID и дедупликации изменены существующие TSX;
новых компонентов и запусков генератора на этом этапе не потребовалось.

## Проверки

Из каталога приложения: `pnpm run lint`, `pnpm run check-types`, `pnpm run build`.
Для изолированной браузерной проверки используются `VITE_BACKEND_URL`,
`VITE_HOST`, `VITE_PORT`, `VITE_HTTPS` в окружении процесса; рабочие env-файлы
менять не требуется. Скриншоты и отчёты находятся в корневой
`.artifacts/react-admin-panel/images-gallery-<сессия>/`.

Для приёмки дедупликации проверяются новая загрузка, повтор тех же байтов под
другим именем (без PUT/complete), гонка complete с каноническим ID, отдельные
счётчики, открытие reused-результата, поиск по короткому ID и скопированному URL,
копирование ID/URL, отмена проверки и передачи, сообщение `IMAGE_HASH_MISMATCH`,
узкая/промежуточная/широкая панели и клавиатура. Используется отдельная БД и
собственная браузерная сессия; пользовательская текущая БД не участвует.
