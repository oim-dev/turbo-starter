# Библиотека файлов

Экран `/files` доступен по `files.read`. Загрузка и версии требуют `files.upload`,
классификация и выбор текущей версии — `files.update`. Постоянные ссылки публичны
и сохраняют имя документа независимо от имени выбранной версии. Поле «Имя файла»
переименовывает документ, URL и скачиваемый файл; исходные имена версий сохраняются.
«Открыть» использует inline: PDF и поддерживаемые браузером медиа открываются
штатным просмотрщиком, MD и другие текстовые исходники — обычным текстом.
«Скачать» использует URL с `download=1` и attachment. MIME определяет backend
по исходному расширению версии; переименование документа его не меняет.
Открытие и скачивание проходят потоком через Client API без редиректа:
bucket и подписанный S3 URL в публичный браузер не передаются.

## Владельцы

- `domains/files` — модели документов/версий, runtime-проверки ответов, адаптеры
  generated SDK, ожидаемые ошибки, SWR и синхронизация кеша после записи.
- `compositions/screens/files` — фильтры, выбор документа, назначение DnD и
  подключение непосредственных вложенных юнитов через фасеты.
- `file-list` — таблица на широком экране и карточки на узком; `file-row` — внутренняя
  реализация, без дополнительного фасета.
- `file-upload` — единственная очередь локальных файлов, классификация новых
  документов, прогресс, AbortController и контрольные точки ручного повтора.
- `file-details` — паспорт, форма классификации, история. Внутренние компоненты
  не имеют дополнительных фасетов.
- `infra/backend-admin-api` — существующий единый транспорт и generated SDK.
- `infra/presigned-upload`, `infra/file-digest`, `infra/native-file-drop` — существующие
  XHR, SHA-256 и события переноса.

Граф: screen → вложенные проекции → domains/files → infra. `files` использует
публичный auth API для identity и терминального 401. Дети не импортируют экран
или соседние юниты. Маршрут подключён через `PermissionBoundary`.

## Сценарии

- Перенос с устройства на страницу сразу открывает загрузчик; передача начинается
  после явного «Загрузить». Открытый загрузчик сам принимает следующие drop,
  listener страницы отключён.
- В открытом паспорте ready-документа drop создаёт **новую версию этого документа**.
  Название цели показано в overlay и modal. Для версии один файл, лишние получают
  пояснение. Есть кнопка «Добавить новую версию».
- Текст/URL не превращаются в файлы, каталоги не обходятся. Без права upload
  навигация браузера предотвращается, показывается пояснение.
- Принимаются любые файлы, включая бинарные, видео, файлы без расширения и пустые.
  `accept`, whitelist расширений и проверка максимального размера удалены.
  Фильтр предопределённых форматов на странице также удалён.
- Очередь проверяет SHA-256 до create порциями по 2 МиБ через `hash-wasm`, не
  загружая весь файл в память. У хеширования свой WASM instance на операцию.
- Проверка хеша и подтверждение — именованные этапы; процент только у XHR-передачи.
  Дубли пропускают PUT. Для крупных файлов используется multipart: сервер выдаёт
  свежий URL каждой части, клиент передаёт `Blob.slice()`. Контрольная точка хранит
  UUID попытки, SHA-256, размер части, следующую часть и факт успешной передачи.
  Явный повтор после ошибки complete подтверждает ту же попытку; после истечения
  создаёт новую. Автоматического повтора POST нет.
  Общие timeout передачи/complete для файлов отключены; отмена остаётся доступной.
- Остановка прерывает текущую передачу, сохраняя очередь. Поздний progress
  игнорируется. Пока передача активна, закрытие modal блокируется; закрытие вкладки
  использует beforeunload. При unmount контроллер отменяется.
- Квитанция дедупликации показывает **совпавшую версию**, включая историческую.
  Основной список копирует ссылку с текущим именем документа. История содержит отдельные адреса
  `?version=N` и `?version=N&download=1`. URL формирует только сервер.
  Копирование в списке, карточке и истории раскрывает кириллицу и пробелы в имени.
  Разделители URL и буквальный процент сохраняют кодирование; адрес остаётся
  эквивалентным серверному, параметры версии не меняются.
- В истории «Текущая» отмечает версию, выдаваемую по постоянной ссылке.
  «Сделать текущей» переключает её через доменное действие и обновляет связанные
  GET-запросы. Новая загрузка становится текущей, но не меняет постоянный URL.
  После возврата к старой версии нумерация новых продолжается по всей истории.
  Действие требует `files.update`, блокирует повтор до ответа и показывает
  результат или исправимую ошибку рядом с историей.
- Первое имя берётся из загруженного файла. Новые версии и переключение его не
  меняют. Переименование обновляет имя и ссылки через общий файловый GET-кеш.
  Публичный API требует revalidation и меняет ETag при смене версии или имени:
  повторное открытие не использует устаревшие байты. Исторические ссылки сохраняются.

Серверные данные живут в SWR: `['private', userId, 'files/<resource>', …]`.
Identity получается внутри hooks, сессии изолирует существующий AuthProvider.
После записи активные GET перечитываются с сохранением данных при revalidation.
Ошибка чтения не отменяет успешную запись. Форма Mantine uncontrolled сохраняет
dirty-ввод при фоновых GET и ошибках.

## Создание TSX

Из `apps/react-admin-panel` выполнены `pnpm run create`:

```text
ui-unit files src/compositions/screens
ui-unit file-list src/compositions/screens/files/ui
ui-unit file-upload src/compositions/screens/files/ui
ui-unit file-details src/compositions/screens/files/ui
ui-component file-row src/compositions/screens/files/ui/file-list/ui
ui-component upload-entry src/compositions/screens/files/ui/file-upload/ui
ui-component file-classification src/compositions/screens/files/ui/file-details/ui
ui-component file-versions src/compositions/screens/files/ui/file-details/ui
ui-component file-drop-overlay src/compositions/screens/files/ui
```

`files.tsx` адаптирован в `files.screen.tsx`. Содержимое шаблонов заменено,
публичные props адаптированы; глубоких импортов самостоятельных юнитов нет.

## Проверка

`pnpm run lint`, `pnpm run check-types`, `pnpm run build`. Браузерная сессия
`files-20261012-astra` использует отдельные API, БД и S3. Проверяются DnD страницы
и версии, upload, дедуп без PUT, история, PDF viewer, скачивание, копирование/поиск
URL, ошибки, отмена/повтор, формы и клавиатура. Viewport: 390×844, 900×900, 1440×1000.
Артефакты: `.artifacts/react-admin-panel/files-20261012/`.

Доработка произвольных файлов и потоковой выдачи использует сессию
`files-unrestricted-20261012`, те же контрольные ширины, отдельные API/БД/S3.
Артефакты — `.artifacts/react-admin-panel/files-unrestricted-20261012/`.
Новых TSX для этой доработки не создавалось.
