# React Admin Panel

`@oim/react-admin-panel` — админка на React, TypeScript, Vite и Mantine.
Вход, личный профиль и управление пользователями, ролями и Keycloak по правам доступа.
Панель управления открывается из меню пользователя.
Общая медиатека доступна по `/images` при праве `images.read`: загрузка оригиналов,
папки и теги, поиск, адаптивные превью и подробные метаданные.
Файлы можно перетаскивать на страницу или добавлять в открытую очередь загрузки.
Готовые размеры в исходных пропорциях сгруппированы по форматам во вкладках подробностей.
Оригиналы проверяются по SHA-256 до загрузки: повторные файлы открывают существующее
изображение без изменения его классификации. В очереди раздельно показаны новые
и уже имеющиеся файлы. Короткий ID и читаемые URL можно копировать из подробностей
и вставлять в поиск. Проверка файлов до 20 МиБ требует HTTPS или localhost.
Запись требует `images.upload` или `images.update` по выполняемой операции.

Документы доступны по `/files`: S3, SHA-256-дедупликация, постоянные ссылки с именем,
просмотр PDF, медиа и текстовых файлов, скачивание и история версий. Перетаскивание на страницу открывает
загрузчик, в открытом паспорте — загрузчик новой версии. Обычная ссылка отдаёт
выбранную текущую версию, `?version=N` — конкретную. Имя документа и URL меняются
только при переименовании, исходные имена версий сохраняются. Текущую версию можно
переключить в истории; браузер проверяет актуальность кеша. Права: `files.read/upload/update`.
Разрешены любые типы файлов, включая видео, без прикладного лимита размера.
Большие файлы хешируются и передаются частями; публичные ссылки отдаёт API
потоком без перенаправления на S3.

## Локальный запуск

Нужны Node.js 24+, pnpm из корневого `packageManager` и PostgreSQL с применёнными
миграциями — см. [настройку backend](../nest-backend/README.md).

Из корня репозитория:

```sh
pnpm install
pnpm --filter @oim/nest-backend run dev:admin
```

В другом терминале, также из корня:

```sh
pnpm run admin:dev
```

- Админка: http://localhost:3001.
- Swagger Admin API: http://localhost:4001/docs.
- На пустой БД создаётся владелец `admin` / `admin`; повторный запуск не сбрасывает пароль.
- Настройки: [.env.example](.env.example), локальные значения — в `.env.local`.
  По умолчанию `/api/*` проксируется в `http://127.0.0.1:4001` с удалением `/api`.
- Для авторизации используйте `localhost` либо HTTPS.

## Проверки и сборка

Из корня репозитория:

```sh
pnpm run admin:lint
pnpm run admin:check-types
pnpm run admin:build
pnpm run admin:preview
```

Команды `admin:dev`, `admin:lint`, `admin:check-types` и `admin:build` собирают необходимый SDK.
`preview` запускается после сборки,
использует тот же порт 3001 и требует работающего Admin API; перед ним остановите dev-сервер.

## Браузерный инструмент

`agent-browser` установлен в приложении. Конфигурация — [agent-browser.json](agent-browser.json),
правила проверки — [AGENTS.md](AGENTS.md#проверка-через-agent-browser).
Команды выполняются из `apps/react-admin-panel`:

```sh
pnpm run browser:install
SESSION="admin-check-$(date +%s)-$$"
pnpm run browser --session "$SESSION" open http://localhost:3001
pnpm run browser --session "$SESSION" snapshot -i
pnpm run browser --session "$SESSION" close
```

`browser:install` однократно скачивает Chrome в кеш машины; на Linux при нехватке
системных библиотек добавьте `--with-deps`. Для каждой задачи используйте уникальную сессию.
Скриншоты сохраняйте в корневом `.artifacts/react-admin-panel/<имя-сессии>/` — каталог исключён из Git.

### Доменные группы

Локальное дополнение к архитектурному профилю React SPA действует для `src/domains/`:

- `management/` — управление самой админкой: административная сессия и профиль,
  аккаунты сотрудников, роли, права и настройки корпоративного входа.
- `application/` — предметные области пользовательских приложений, включая их
  пользователей, роли и авторизацию. Каталог зарезервирован файлом `.gitkeep`;
  при добавлении первого домена этот файл можно удалить.
- Самостоятельные сквозные домены могут находиться прямо в `domains/`: `files/`
  владеет документами и их версиями; `images/`
  владеет общей медиатекой для административных и прикладных сценариев. Группы
  `shared`, `common` и `media` ради одного домена не создаются. Связь изображения
  с аватаром принадлежит домену аккаунта, который зависит от публичного API `images`.

Текущая структура:

```text
src/domains/
├── files/
├── images/
├── application/
│   └── .gitkeep
└── management/
    ├── auth/
    ├── access/
    └── keycloak-settings/
```

Группы содержат доменные юниты и другие группы, собственного кода и фасетов у них нет.
Каждый домен владеет своим публичным `index.ts`; потребители используют алиас слоя
и полный путь домена, например `domains/management/auth` или `domains/management/access`.
Внутри юнита импорты относительные. Межюнитные зависимости проходят через фасеты
и подчиняются матрице слоёв и запрету циклов Unit Architecture.

`management/auth` отвечает за сессию сотрудника во всей админке, включая вход и профиль
за пределами URL `/management`. `management/access` объединяет управление аккаунтами,
ролями и назначением прав; он и `management/keycloak-settings` используют публичный API
`management/auth`.

Принадлежность к группе определяется владельцем данных и правил, а не URL или совпадением
названий. Одноимённые сущности `management` и `application` имеют самостоятельные модели
и контракты. Общую возможность выделяем только при подтверждённой общей ответственности
и реальных потребителях.

### Проектные SVG

Исходники находятся в `src/shared/svg`. Спрайт собирается через `@gromlab/svg-sprites@2.1.0`
в режиме `react@vite` по явному списку файлов в
[`svg-sprite.config.json`](src/infra/app-icons/svg-sprite.config.json).
Компоненты импортируют `AppIcon` через публичный фасет `infra/app-icons`.

`pnpm run sprites` из каталога приложения пересобирает спрайт. Генерация также встроена
в `dev`, `build` и `check-types`. Каталог `.svg-sprite` создаётся генератором и исключён из Git.

Логотип BIOCAD использует `icon="biocad-logo"`. Его размеры задаются классом `brandLogo`
в `admin-sidebar.module.css`; пропорции сохраняются и в компактном меню. Генератор заменяет
исходный цвет на `var(--icon-color-1, currentColor)`, а ссылка логотипа наследует цвет
текущей темы через `--app-color-text-strong`. Переходы цветов спрайта отключены в конфигурации.

## Поставка

[Dockerfile](Dockerfile) собирает SDK и SPA; nginx раздаёт приложение с fallback для маршрутов.
Внешний reverse proxy должен направлять `/api/*` в Admin API с удалением префикса `/api`.
