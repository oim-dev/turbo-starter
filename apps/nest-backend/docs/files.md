# Файлы и версии

Библиотека принимает любые файлы: документы, архивы, бинарные данные, сырое видео,
файлы без расширения и пустые файлы. Allowlist типов, анализ содержимого и
прикладной лимит размера отсутствуют. Размер хранится в PostgreSQL BIGINT.
В JSON передаётся точное целое число байтов, совместимое с browser `File.size`.

## Постоянная публичная ссылка

```text
/files/aB3dE6gH/Инструкция.pdf
/files/aB3dE6gH/Инструкция.pdf?version=2
/files/aB3dE6gH/Инструкция.pdf?version=2&download=1
```

Client API сам отдаёт поток из приватного S3. В ответе нет редиректа, `Location`,
bucket, object key или подписанного S3 URL. Адрес в браузере остаётся постоянным
URL приложения. S3 используется только внутри сервера публичной выдачи.

Без `version` выбирается текущая редакция документа. Новая подтверждённая загрузка
становится текущей; администратор с `files.update` может выбрать любую сохранённую
редакцию через `PATCH /files/:id/current-version` с `{version: N}`.
Номер следующей редакции всегда больше всех номеров в истории, даже после отката.
Новая незавершённая
загрузка не меняет выдачу. `version=N` фиксирует конкретную редакцию; неизвестная
версия даёт 404. ID постоянен, имя в пути — читаемая часть; реальные имя и байты
берутся из БД. Имя документа по умолчанию берётся из первой загрузки. Загрузка
или выбор версии с другим именем не меняет имя документа, `url` и `downloadUrl`.
`PATCH /files/:id` с `{title: "Новое имя.pdf"}` переименовывает документ: его
`title`, `filename` и `publicFilename` синхронно получают новое имя. Оно используется
в интерфейсе, сегменте URL и `Content-Disposition` обычной ссылки. Переименовывать
можно многократно; прежние URL продолжают выдавать текущую версию с новым именем.
Имена, ссылки и заголовки скачивания конкретных версий (`?version=N`) неизменны.

Обычная ссылка выдаётся с `Content-Disposition: inline`, `download=1` — с
`attachment`. Видео, аудио, изображения и PDF используют MIME своей версии;
фактическое воспроизведение зависит от поддержки формата/кодека браузером.
Текстовые исходники (включая MD, HTML, JSON, XML и SVG) при просмотре отдаются как
`text/plain; charset=utf-8`, поэтому открываются текстом. Скачивание возвращает
исходный MIME и те же байты. Неизвестный тип — `application/octet-stream`;
встроенный просмотрщик для неподдерживаемых браузером форматов не создаётся.
Имя отдаётся
через UTF-8 `filename*`. Поддержаны GET, HEAD, `Content-Length`, `Accept-Ranges`,
одиночный `Range` (206/416), `ETag`, `If-None-Match` (304) и `If-Range`.
`Cache-Control: private, no-cache, max-age=0, must-revalidate` разрешает браузеру
хранить файл, но требует проверки актуальности перед повторным использованием.
ETag учитывает ID версии, SHA-256, выдаваемое имя, дату изменения, MIME ответа и inline/attachment.
После загрузки, выбора версии или переименования старый валидатор получает 200
с актуальными байтами и заголовками; неизменившийся ответ допускает 304.
Для ссылки без `version` Last-Modified берётся из даты изменения документа, а не
старой даты создания выбранной редакции. If-Range с датой для такой ссылки
возвращает полный ответ: секундная точность не различает быстрые переключения.
Сильный актуальный ETag разрешает 206; устаревший — полный 200.
Поток не буферизуется
целиком; закрытие клиентского соединения закрывает чтение S3. Ошибка после начала
передачи обрывает соединение, а не выдаёт усечённый файл за успешный.

Ссылки доступны всем, у кого они есть. В посте сохраняйте UUID документа либо
постоянную ссылку; для фиксированной редакции — ссылку с `version`.

## Владение и данные

- `StoredFile`: постоянная идентичность, название, папка, теги, автор и текущая версия.
  `currentVersionId` ссылается на неизменяемую редакцию; `currentVersion` в DTO — её номер.
- `FileVersion`: неизменяемая редакция с последовательным номером, именем и автором.
- `FileBlob`: единственные байты с уникальным проверенным SHA-256, размером и S3 key.
- `FileUpload`: отдельная попытка передачи, заявленный хеш, срок действия,
  multipart session/part size и сохранённый результат подтверждения.

`modules/files` владеет правилами. Общие операции S3 — `ObjectStorage` и
`StorageConfig`. Контроллер публичной выдачи принадлежит Client API. Номера
редакций независимы от S3 versioning. Метаданные меняются независимо от байтов.

MIME определяется на сервере через `mime-types` по исходному расширению при
создании загрузки, сохраняется в FileUpload/FileVersion и передаётся в S3 как
Content-Type (PUT, multipart и фиксация объекта, включая multipart copy).
Это метаданные формата, не проверка содержимого: браузерный File.type не является
источником истины, S3 автоматически MIME не определяет. При дедупликации несколько
версий могут ссылаться на один blob, поэтому публичная выдача использует MIME
версии, а не метаданные общего объекта. Старые записи с application/octet-stream
уточняются при чтении по расширению версии, без перезагрузки объектов.

## Admin API

| Метод | Назначение | Права |
| --- | --- | --- |
| `GET /files` | Список, поиск, пагинация | `files.read` |
| `GET /files/facets` | Папки и теги | `files.read` |
| `GET /files/:id` | Метаданные текущей версии и постоянные ссылки | `files.read` |
| `GET /files/:id/versions` | История, новые первыми | `files.read` |
| `POST /files/uploads` | Новый файл или найденный дубль | `files.read`, `files.upload` |
| `POST /files/:id/versions/uploads` | Новая версия | `files.read`, `files.upload` |
| `POST /files/uploads/:id/parts/:part` | Подписать часть multipart | `files.read`, `files.upload` |
| `POST /files/uploads/:id/complete` | Проверить и опубликовать | `files.read`, `files.upload` |
| `PATCH /files/:id` | Название, папка, теги | `files.update` |
| `PATCH /files/:id/current-version` | Выбор текущей версии, `{version: N}` | `files.update` |

Права несистемные: OWNER/ADMIN получают их автоматически. JWT Client и Admin
не взаимозаменяемы. Каталог фильтруется по имени, историческому имени, тегам,
UUID/publicId/URL, папке, статусу; API также принимает произвольное расширение.
`/files/policy` удалён вместе с ограничениями загрузки.

## Передача, целостность и дедупликация

Клиент считает SHA-256 порциями по 2 МиБ (`hash-wasm`), не читая большой файл целиком
в память. Создание принимает `{filename,byteSize,sha256,folder?,tags?,title?}`,
для версии — `{filename,byteSize,sha256}`. Повторные байты переиспользуются по
проверенному хешу и точному размеру независимо от имени и расширения.

Ответ создания при совпадении:
`{file,version,reused:true,uploadId:null,upload:null}`. Для нового документа
возвращается существующий документ и именно совпавшая версия, включая старую.
Для версии текущие одинаковые байты не создают лишний номер; возврат к старым
байтам после другой редакции создаёт новую версию, используя существующий blob.

Если нужна передача: `{file,version:null,reused:false,uploadId,upload}`:

- Менее 32 МиБ: `upload.method=PUT`, `url`, `headers`, `partSize=null`.
- От 32 МиБ: `upload.method=MULTIPART`, `url=null`, `partSize`. Это выбор транспорта,
  не предел размера. Размер части увеличивается, чтобы укладываться в 10000 частей
  протокола S3. Физические ограничения объекта/частей определяются провайдером S3.
- Для каждой части клиент получает свежий URL через POST `parts/:part` и отправляет
  `Blob.slice()` прямо в S3. JWT/cookie API к S3 не передаются. Подтверждённые части
  запоминаются в локальной очереди для ручного продолжения.
- Попытка действует сутки без активности, выдача части продлевает её. Ссылка на
  одну часть действует 15 минут. Создание S3 session происходит вне транзакции;
  CAS выбирает одну session при конкурентной инициализации.
- Complete читает список, номера и размеры частей непосредственно из S3 и
  собирает staging. Потеря ответа CompleteMultipartUpload восстанавливается по
  существующему собранному объекту; повтор завершения безопасен.

Сервер фиксирует staging в уникальном объекте с условием ETag/versionId. Объекты
свыше 5 ГиБ копируются через server-side multipart copy. Затем сервер потоково
проверяет точное число байтов и SHA-256. Проверки MIME/расширения/кодировки нет.
Проверка размера означает целостность передачи, а не верхний лимит.

Сеть и хеширование вне DB-транзакции. В короткой транзакции создаются blob, версия
и постоянный результат попытки. Блокировки идут admin → upload → blob → document.
UNIQUE SHA-256 объединяет одновременные дубли. Повтор `complete` возвращает ту же
версию; старая staging-ссылка не может изменить опубликованные байты.

При ошибке целостности возвращаются `FILE_HASH_MISMATCH` или `FILE_SIZE_MISMATCH`;
неполная multipart-передача — `UPLOAD_NOT_AVAILABLE`, истёкшая — `UPLOAD_EXPIRED`.
Автоматического повтора создания нет. Ожидание передачи и проверки больших файлов
в браузере не ограничено общим таймером; отмена пользователем сохраняется.
S3 idle timeout ограничивает зависший транспорт, а не длительность активной передачи.

## Настройка и очистка

Общие `S3_*` остаются прежними. `FILE_PUBLIC_BASE_URL` (default
`http://localhost:4000`) задаёт внешний Client API. `FILE_MAX_UPLOAD_BYTES` удалён.
Reverse proxy публичного API должен пропускать потоковые ответы и Range, а его
таймауты для complete должны соответствовать длительным проверкам крупных файлов.

Инфраструктура задаёт lifecycle только для `files/staging/`: сутки для текущих
и нетекущих объектов. `FileUploadCleanup` отменяет S3 multipart истёкших попыток;
CAS защищает от гонки с продлением. Для multipart, оставшихся после аварии между
созданием S3 session и записью её ID, нужна уборка incomplete uploads средствами S3.
`files/objects/` не очищается по возрасту: после неясного COMMIT orphan можно удалять
только после сверки с `FileBlob`. Опубликованные версии сохраняются.

Миграция `20261012180000_unrestricted_files` расширяет размеры до BIGINT,
расширения до 255 символов, разрешает нулевой размер и добавляет multipart-поля,
сохраняя прежние файлы и ссылки. Исторические миграции не переписываются.

Миграция `20261012200000_file_current_version` сохраняет текущую публикацию как
ссылку на редакцию и фиксирует имя постоянного URL из первой версии (для ещё
не загруженных — из карточки). Выбор текущей версии не меняет историю, название,
папку и теги; размер, тип и SHA-256 в карточке соответствуют выбранной версии.

Миграция `20261012210000_file_document_name` синхронизирует имя документа и URL
с уже заданным пользователем названием (при пустом названии — с первоначальным
именем). Исходные имена в FileVersion не изменяются.

Проверки: lint, check-types, build, OpenAPI/SDK, env:check и ручные HTTP/браузерные
сценарии на изолированной БД и S3. Артефакты текущей доработки:
`.artifacts/nest-backend/files-unrestricted-20261012/`.
