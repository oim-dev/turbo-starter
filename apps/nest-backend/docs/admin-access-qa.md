# Приёмка ролей и настроек Keycloak — 2026-10-09

Этот отчёт фиксирует состояние до удаления служебного CLI. Последующая автоматическая
инициализация и UI-операции привязок проверены в [backend-startup-qa.md](backend-startup-qa.md).

## Среда

Проверки выполнены на собственных временных контейнерах PostgreSQL 16 и Keycloak
26.8.0, без пользовательских volumes и существующей БД. Использовались отдельные
loopback-порты, synthetic accounts/secrets и явный DATABASE_URL. Пользовательские
env-файлы не читались и не изменялись. Для browser flow backend запускался из
`/tmp/opencode` в development, без загрузки пользовательского `infra/dev/.env`.

Браузер — отдельный процесс Chromium через Playwright 1.63.0; общие вкладки MCP
не использовались. SPA проверялась из production build через изолированный preview/proxy.

## Подтверждено

- Backend: lint, check-types с Prisma generation, build обоих API.
- Admin SDK: штатная генерация 19 операций, check-types и build.
- React SPA: lint, check-types через build, production build.
- Client OpenAPI не имеет diff; Client SDK и клиентские HTTP-контроллеры не менялись.
- Все 21 миграция применены к чистой БД. `prisma migrate diff` — `No difference detected`.
- Seed в production создаёт admin/admin с OWNER; повторный seed не меняет credentials.
  После переименования аккаунта повторный seed не восстанавливает login admin.
- OWNER получает все permissions. ADMIN и USER получают 403 на системных API.
- Дополнительная роль создаётся с выбранными permissions, назначается аккаунту;
  запрещённая смена пароля возвращает 403. Изменение роли отзывает старый JWT (401).
- Системные permissions в дополнительной роли — 400, изменение встроенной роли — 400,
  удаление назначенной роли и понижение последнего OWNER — 409.
- Изменение имени сохраняет сессию; смена собственного логина отзывает старый JWT.
- Secret записан в БД в AES-GCM envelope, не равен исходному значению; GET/PUT response
  содержит только hasSecret и не содержит plaintext. Устаревшая версия настроек — 409.
- Замена client ID без нового secret — 400. Запрос login без Origin/CSRF — 403.
- Реальный Keycloak: OWNER включил провайдера через форму SPA, secret после сохранения
  очищен из поля. SSO-only USER прошёл настоящую форму KC, callback и ровно один complete (200).
- USER не видит системную навигацию, прямой `/access` показывает отказ.
- Изменение настроек отзывает собственную SSO-сессию; после reload необходим новый вход.
  Старый callback после обновления конфигурации возвращает keycloak_invalid.
  Локальная сессия после изменения конфигурации остаётся действующей.
- В UI созданы роль и аккаунт с этой ролью, затем роль аккаунта изменена на ADMIN (200).
- В UI изменены имя и пароль USER; после смены пароля выполнены выход, вход новым
  паролем и reload с восстановлением сессии. Page errors в завершённых сценариях отсутствовали.
- Новые direct URLs сохраняются после локального входа. Keycloak и Access проверены
  на 1440px и 390px; мобильного горизонтального overflow нет, проверена тёмная тема.

## Найдено и исправлено в ходе приёмки

- PostgreSQL advisory lock возвращал `void`, который Prisma adapter не десериализует:
  результат приведён к `text`, системные HTTP-записи повторно проверены успешно.
- У новой миграции исправлен default updatedAt; финальная версия заново применена
  к отдельной чистой БД и проверена через migrate diff.
- Новые приватные пути добавлены в allowlist безопасного возврата после входа.
- Формы используют Mantine Fieldset без браузерной рамки и с min-width=0.

## Границы проверки

Это локальная проверка настоящего Keycloak, не корпоративной production-конфигурации.
MFA, смена JWKS, production reverse proxy и миграция копии production-данных в этой
задаче не проверялись. Исторические доказательства OIDC протокола находятся в
`admin-keycloak-qa.md` и не приписываются этим новым сценариям.
Vite сообщает о размере основного JS chunk около 684 kB; сборка успешна.
Автотесты и тестовый стек в репозиторий не добавлялись.

После проверки собственные backend/preview/browser-процессы остановлены, временные
контейнеры PostgreSQL/Keycloak удалены; пользовательский контейнер PostgreSQL не затронут.
Скриншоты завершённых сценариев сохранены в `/tmp/opencode/auth-rbac-*-final.png`
и `/tmp/opencode/auth-rbac-access-*.png`.
